# Promlive S25 화면

2026-09-18. 제공된 입력바 사진 4장과 후속 왼쪽 페이지 사진 2장을 기준으로 만들었습니다. 시작 화면은 채팅이며 왼쪽 페이지는 Promlive 이름, 둥근 검색바, 채팅방 목록, 하단 사용자 이름·설정 버튼 순서입니다. 배너·탭·카메라·새 채팅 버튼 등 요청에 없는 추가 요소는 표시하지 않습니다.

채팅방에는 원형 아이콘, 제목, 마지막으로 저장된 메시지, 시간을 표시합니다. 검색은 제목과 마지막 메시지 미리보기를 대상으로 동작합니다. 하단 영역은 목록 스크롤과 분리해 고정했습니다. 실제 프로필은 아직 연결하지 않아 이름은 `사용자`이며 설정 버튼에서는 설정 화면 목업을 열 수 있습니다.

## 상단 배치와 목록 열림 상태

2026-09-19 후속 사진 `photo_6156823455928619202_y.jpg`의 618px 너비를 기준으로 목록 버튼을 다시 측정했습니다. 좌표는 상태 표시줄 아래의 콘텐츠 영역 기준이며 `src/features/chat/chatAppearance.ts`의 `referenceHeader`에 모았습니다. 제목·검색·설정의 캡슐 구성은 앞서 요청한 사진의 구성을 유지하고 목록 버튼과 높이를 맞췄습니다.

| 영역 | 사진 기준 x / y | 사진 기준 너비 / 높이 |
|---|---|---|
| 뒤로가기 버튼 | 27 / 0 | 76 / 76 |
| 제목 캡슐 | 123 / 0 | 330 / 76 |
| 검색·설정 캡슐 | 463 / 0 | 144 / 76 |

후속 요청에 따라 기존 세 줄 목록 아이콘을 `photo_6156966405325132146_y.jpg`처럼 왼쪽 화살표로 교체했습니다. 버튼을 누르면 채팅 목록으로 돌아갑니다. 버튼의 위치·크기와 상단 전체가 차지하는 높이는 유지했습니다. 버튼은 테두리 없는 `#292929`이며 제목과 검색·설정 캡슐도 같은 배경색을 사용합니다.

검색 버튼은 기존 채팅 내역의 검색 화면을 엽니다. 설정은 사진처럼 세로 점 아이콘으로 표시하며, 하단 설정과 같은 설정 목업을 엽니다. 제목과 아이콘은 현재 채팅방을 표시합니다.

목록을 열면 오른쪽 채팅 화면 전체를 가로·세로 동일하게 90%로 축소합니다. 후속 사진 `photo_6156823455928619200_y.jpg`에서 측정한 목록 배경은 `#1F1F1F`, 오른쪽 채팅 배경은 `#1A1A1A`입니다. 채팅 위에 목록 배경색을 61% 불투명도로 겹쳐 기존 `#111111` 배경을 밝히면서 아이콘·글자·입력바의 대비를 함께 낮춥니다. 완전히 열렸을 때 버튼 배경은 참고 사진처럼 `#232323`이 됩니다. 입력바, 본문 배치, 기존 제스처·햅틱 동작은 유지했습니다.

선택 하이라이트는 후속 사진 `photo_6156823455928619207_y.jpg`에서 측정한 균일한 `#2A2A2A` 배경과 20dp 둥근 모서리로 표시합니다. 현재 채팅방에만 유지되며 다른 채팅방을 열면 선택 표시도 이동합니다. 누르는 동안은 `#2D2D2D`를 사용합니다. 채팅방 행의 크기와 내용 배치는 그대로 유지했습니다.

1080px 에뮬레이터에서 뒤로가기 버튼의 실제 경계는 `[47,63][180,196]`이며 상태 표시줄 63px을 제외한 배치 기준 사진 환산값과의 차이는 0.5px 이내입니다. 닫힌 화면·열린 목록·오른쪽 채팅·버튼의 배경색은 에뮬레이터 캡처의 실제 픽셀로 확인했습니다. 이는 측정한 영역의 배치와 색상 확인이며 Samsung 실기기의 글꼴·아이콘 렌더링까지 100% 동일함을 뜻하지는 않습니다.

## 설정 화면 목업

채팅 상단의 세로 점 버튼과 목록 하단의 설정 버튼에서 같은 목업을 엽니다. 프로필, AI, 대화, 앱 순서로 배치하며 현재 테마와 둥근 카드·버튼을 사용합니다.

- 프로필: 이름 편집 미리보기.
- AI: Grok 연결 상태, 기본 모델 선택 예시, 응답 스타일 선택.
- 대화: 글자 크기 미리보기, 터치 진동·응답 알림 스위치.
- 앱: 앱 전체에 적용되는 다크·라이트·시스템 테마와 앱 정보.

선택 항목은 하단 선택창으로 표시합니다. 화면 테마는 채팅·목록·설정에 즉시 적용하며 기기에 저장해 재실행 후에도 유지합니다. 그 밖의 값은 닫을 때 초기화되며 실제 프로필, 채팅 설정, 인증·네트워크, 알림 권한이나 저장소에 적용되지 않습니다. AI 연결은 미연결 상태로 표시하고 실제 로그인·키 연결은 나중에 구현합니다.

설정 화면을 띄운 동안 원래 채팅과 목록 상태는 유지합니다. Android 뒤로가기와 웹 Escape는 먼저 선택창을 닫고, 다음에는 설정을 닫아 원래 화면으로 돌아갑니다.

설정, 하단 선택창, 확장 메시지 입력창은 오른쪽에서 들어오며 닫힐 때 오른쪽으로 빠집니다. 버튼·항목 선택·뒤로가기 제스처도 같은 전환을 사용합니다. 시스템의 동작 줄이기가 켜져 있으면 전환 애니메이션을 생략합니다.

설정 화면에서 왼쪽에서 오른쪽으로 밀면 손가락을 따라 화면이 이동하며 이전 채팅 또는 목록 화면이 드러납니다. 너비의 30% 이상 밀거나 24dp 이상 빠르게 밀면 돌아가고, 짧게 밀거나 왼쪽으로 방향을 바꿔 놓으면 제자리로 복귀합니다. 하단 선택창에서도 같은 제스처로 선택창만 닫습니다. 세로 스크롤, 스위치 조작, 이름 입력창 안의 가로 동작은 뒤로가기를 일으키지 않습니다. 돌아가기가 확정될 때 기존과 같은 짧은 시스템 햅틱을 한 번 사용하며 동작 줄이기 설정을 존중합니다.

## 라이트 모드

추가로 제공된 라이트 사진을 직접 측정했습니다. `photo_6156823455928619205_y.jpg`의 목록은 `#F5F5F5`, 밀린 채팅 화면은 `#F9F9F9`, 검색바는 `#FFFFFF`입니다. `photo_6156823455928619203_y.jpg`의 채팅 배경·입력바·상단 버튼은 흰색이며 부드러운 그림자를 사용합니다. 선택 하이라이트는 `photo_6156823455928619208_y.jpg`의 `#EEEEEE`를 적용했습니다.

크기·간격·위치·채팅 목록 구성은 기존과 동일하고 색상·그림자만 테마에 따라 바뀝니다. Promlive 이름은 목록의 브랜드 영역이며 사진의 사용자 이름 위치에 해당하는 상단에 있지만 좌표와 크기를 동일하게 맞춘 것은 아닙니다. 사용자 이름은 계속 목록 하단에 별도로 표시합니다.

설정 → 화면 테마에서 다크·라이트·시스템을 선택할 수 있습니다. `시스템`은 기기의 표시 모드를 따릅니다. Android의 열린 팝업에도 상태·탐색 표시줄 아이콘 색을 반영합니다. 실제 AI 연결과 다른 설정 목업의 동작은 변경하지 않았습니다.

실행 화면: [라이트 채팅](screenshots/android-s25-light-chat.png), [라이트 목록](screenshots/android-s25-light-history.png), [라이트 설정](screenshots/android-s25-light-settings.png).

Android 앱 재실행과 웹 새로고침 후 테마 유지, 다크·라이트 전환, 작성 중 메시지 유지, 설정과 선택창의 뒤로가기·스와이프·세로 스크롤을 확인했습니다. 웹에서 진행 중인 애니메이션을 중단할 때 사용하는 React Native Web의 `global` 참조는 Vite에서 `globalThis`로 연결해 연속 조작 시에도 전환이 완료되게 했습니다.

## 좌우 이동

채팅 화면에서 오른쪽으로 쓸면 화면 전체가 둥근 패널처럼 이동하며 왼쪽 채팅 내역이 드러납니다. 내역에서 왼쪽으로 쓸면 채팅으로 돌아옵니다. 이동 중에는 손가락을 따라가며, 짧고 느린 드래그는 원래 위치로 복귀하고 빠른 스와이프는 진행 방향으로 전환합니다. 상단 뒤로가기 화살표로 목록 열기, 밀려난 채팅 화면을 눌러 닫기, Android 뒤로가기와 웹 Escape도 지원합니다.

세로 스크롤과 입력창·검색창 내부의 선택 동작은 페이지 이동에서 제외했습니다. 전환할 때 키보드는 닫히며 작성 중인 문장은 보존됩니다. 시스템의 동작 줄이기 설정에서는 손을 놓은 뒤 전환 애니메이션을 생략합니다.

Android에서는 열림·닫힘이 확정될 때 짧은 햅틱을 한 번 재생합니다. 드래그를 취소해 원래 화면으로 돌아갈 때는 재생하지 않습니다. Android 14 이상은 `SEGMENT_TICK`, 이전 버전은 `CLOCK_TICK`을 사용합니다. `View.performHapticFeedback`을 사용해 시스템 터치 진동 설정을 따르며 추가 진동 권한이나 강제 진동은 사용하지 않습니다. 진동의 길이·세기는 기기의 프리셋 구현에 따릅니다. 현재 햅틱 연결은 Android용이며 웹·다른 플랫폼에서는 재생하지 않습니다. [Android 햅틱 가이드](https://developer.android.com/develop/ui/views/haptics/haptic-feedback).

Android 12 이상에서는 `WindowInsets.getRoundedCorner`로 각 모서리 반경을 읽어 적용합니다. 값을 제공하지 않는 기기·에뮬레이터와 다른 플랫폼은 기본 32dp를 사용합니다. 현재 S25 크기 에뮬레이터의 시스템 보고 값은 0이므로 기본값으로 확인했습니다. Samsung 실기기의 실제 곡률 일치는 아직 검증하지 않았습니다. 웹과 모바일은 동일한 전환·제스처 컴포넌트를 사용합니다.

## 함께 보면서 수정하기

현재 Mac에 `Promlive_S25_API36`이라는 별도 Android 에뮬레이터를 만들었습니다. 표시 이름은 **Promlive S25**, 해상도는 1080 × 2340, 밀도는 420dpi, OS는 Google APIs Android 16 / API 36입니다. Android Debug 앱과 Metro를 연결하여 소스 수정 시 Fast Refresh를 사용할 수 있습니다.

실제 Samsung One UI 이미지가 아닙니다. 420dpi는 이 미리보기의 설정이며 S25 실기기의 디스플레이 확대·글꼴 설정을 확인한 값은 아닙니다. 사진은 상태 표시줄·내비게이션 영역이 잘려 있고 JPEG로 압축되어 있어 폰트·키보드·안전 영역까지 한 픽셀의 오차도 없다고 보장할 수 없습니다. 실기기의 마지막 확인은 남아 있습니다.

이 컴퓨터에서 다시 실행할 때, 터미널별로 다음을 실행합니다. 이미 실행 중인 Metro와 에뮬레이터는 그대로 사용하면 됩니다.

```sh
cd /Users/codexer/Promlive/storyloom
npm start -- --port 8081
```

```sh
/Users/codexer/Library/Android/sdk/emulator/emulator \
  -avd Promlive_S25_API36 -port 5564 -no-snapshot
```

```sh
cd /Users/codexer/Promlive/storyloom
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home \
ANDROID_HOME=/Users/codexer/Library/Android/sdk \
./android/gradlew -p android assembleDebug --console=plain
/Users/codexer/Library/Android/sdk/platform-tools/adb -s emulator-5564 install -r android/app/build/outputs/apk/debug/app-debug.apk
/Users/codexer/Library/Android/sdk/platform-tools/adb -s emulator-5564 reverse tcp:8081 tcp:8081
/Users/codexer/Library/Android/sdk/platform-tools/adb -s emulator-5564 shell am start -n com.storyloom/.MainActivity
```

프로필 등록은 `~/.android/avd/Promlive_S25_API36.ini`, 에뮬레이터 데이터는 `build/s25.avd`에 있습니다. 이 기기의 로컬 미리보기 설정이므로 Git에 포함하지 않습니다. 앱의 내부 패키지 ID `com.storyloom`은 저장 데이터의 연속성을 위해 유지했습니다.

## 입력바 치수

원본 사진의 너비 618을 기준으로 `화면 논리 너비 / 618` 배율을 적용합니다. 수치는 `src/features/chat/chatAppearance.ts`에 모았습니다. 하단 위치는 OS 안전 영역 위에 고정하며 입력이 길어지면 위로 늘어납니다.

| 항목 | 참고 사진 px | 1080px 에뮬레이터에서 확인 |
|---|---:|---:|
| 좌우 여백 | 20 | 각각 35px |
| 하단 여백 | 20 | 안전 영역 위 35px |
| 기본 높이 | 111 | 194px |
| 한 줄 입력 높이 | 171 | 299px |
| 두 줄 입력 높이 | 208 | 364px |
| 최대 높이 | 265 | 463px |
| 버튼 지름 | 70 | 약 122px |

최대 높이 이후에는 입력 내용이 내부에서 스크롤되고 확대 버튼으로 전체 입력창을 열 수 있습니다. 큰 시스템 글꼴에서는 읽을 수 있도록 높이가 달라질 수 있습니다. 웹과 모바일은 동일한 입력바·내역 컴포넌트를 공유하고, 실제 텍스트 입력만 각 플랫폼에 맞게 렌더링합니다.

## 확인한 동작

- Android에서 빈 입력·한 줄·두 줄·최대 높이의 레이아웃과 위로 확장되는 동작.
- 키보드 열기·닫기 후 입력바 위치 복귀, 최대 높이 내부 스크롤.
- 전체 입력창에서 수정 후 접기, 짧아진 내용에 맞춘 축소.
- 전송 후 기본 높이 복귀, 새 채팅, 내역에서 이전 대화 열기.
- 작성 중 내용의 프로세스 재시작 후 복구.
- 웹 412 × 853 미리보기에서 한글 줄바꿈, 높이 제한, 내역 검색·재열기.

AI 인증·응답, 첨부, 음성 입력은 연결하지 않았습니다. 전송 버튼은 사용자 문장만 SQLite에 저장하며 화면에 `기기에만 저장됨`을 표시합니다. 첨부·음성 버튼은 미연결 안내를 표시합니다.
