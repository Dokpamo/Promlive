Android 앱 재실행과 웹 새로고침 후 테마 유지, 다크·라이트 전환, 작성 중 메시지 유지, 설정과 선택창의 뒤로가기·스와이프·세로 스크롤을 확인했습니다. 웹에서 진행 중인 애니메이션을 중단할 때 사용하는 React Native Web의 `global` 참조는 Vite에서 `globalThis`로 연결해 연속 조작 시에도 전환이 완료되게 했습니다.

## 좌우 이동

채팅 화면에서 오른쪽으로 쓸면 화면 전체가 둥근 패널처럼 이동하며 왼쪽 카드 목록이 드러납니다. 카드의 채팅 기록에서 왼쪽으로 쓸면 카드 목록으로, 다시 왼쪽으로 쓸면 채팅으로 돌아옵니다. 상단 뒤로가기 화살표와 Android 뒤로가기·웹 Escape도 한 단계씩 이동합니다. 밀려난 채팅 화면을 누르면 바로 채팅으로 돌아옵니다.

채팅에서 왼쪽으로 쓸면 오른쪽에 나란히 놓인 빈 포켓 페이지로 이동합니다. 포켓은 채팅과 같은 단계이며 설정 모달이나 메모장이 아닙니다. 오른쪽으로 쓸면 채팅으로 돌아오며 작성 중인 메시지와 선택한 대화가 유지됩니다. 두 페이지는 화면 두 배 너비의 하나의 면에 빈틈없이 붙어 함께 이동합니다. 둥근 모서리는 합쳐진 면의 바깥쪽 네 곳에만 적용하고, 가운데 연결부에는 곡률·틈·그림자가 없습니다. 정지하면 화면 전체를 채웁니다. 제작자 설정을 연결할 수 있도록 `ChatDrawer`는 `pocketEnabled` 입력을 받으며 현재 미리보기에서는 기본으로 켜져 있습니다. 제작자용 설정 UI와 포켓 콘텐츠는 아직 추가하지 않았습니다.

이동 중에는 손가락을 따라가며, 짧고 느린 드래그는 원래 위치로 복귀하고 빠른 스와이프는 진행 방향으로 전환합니다. 한 번의 제스처로 서로 다른 두 단계를 연속해서 넘기지 않습니다. [S25 이동 중 화면](screenshots/android-s25-pocket-joined.png)에서 가운데 연결부가 위아래까지 평평하게 이어지는 것을 확인했습니다.

세로 스크롤과 입력창·검색창 내부의 선택 동작은 페이지 이동에서 제외했습니다. 전환할 때 키보드는 닫히며 작성 중인 문장은 보존됩니다. 시스템의 동작 줄이기 설정에서는 손을 놓은 뒤 전환 애니메이션을 생략합니다.

Android에서는 열림·닫힘이 확정될 때 짧은 햅틱을 한 번 재생합니다. 드래그를 취소해 원래 화면으로 돌아갈 때는 재생하지 않습니다. Android 14 이상은 `SEGMENT_TICK`, 이전 버전은 `CLOCK_TICK`을 사용합니다. `View.performHapticFeedback`을 사용해 시스템 터치 진동 설정을 따르며 추가 진동 권한이나 강제 진동은 사용하지 않습니다. 진동의 길이·세기는 기기의 프리셋 구현에 따릅니다. 현재 햅틱 연결은 Android용이며 웹·다른 플랫폼에서는 재생하지 않습니다. [Android 햅틱 가이드](https://developer.android.com/develop/ui/views/haptics/haptic-feedback).

Android 12 이상에서는 `WindowInsets.getRoundedCorner`로 각 모서리 반경을 읽어 적용합니다. 값을 제공하지 않는 기기·에뮬레이터와 다른 플랫폼은 기본 32dp를 사용합니다. 현재 S25 크기 에뮬레이터의 시스템 보고 값은 0이므로 기본값으로 확인했습니다. Samsung 실기기의 실제 곡률 일치는 아직 검증하지 않았습니다. 웹과 모바일은 동일한 전환·제스처 컴포넌트를 사용합니다.

## 함께 보면서 수정하기

현재 Mac에 `Promlive_S25_API36`이라는 별도 Android 에뮬레이터를 만들었습니다. 표시 이름은 **Promlive S25**, 해상도는 1080 × 2340, 밀도는 420dpi, OS는 Google APIs Android 16 / API 36입니다. Android Debug 앱과 Metro를 연결하여 소스 수정 시 Fast Refresh를 사용할 수 있습니다.

실제 Samsung One UI 이미지가 아닙니다. 420dpi는 이 미리보기의 설정이며 S25 실기기의 디스플레이 확대·글꼴 설정을 확인한 값은 아닙니다. 사진은 상태 표시줄·내비게이션 영역이 잘려 있고 JPEG로 압축되어 있어 폰트·키보드·안전 영역까지 한 픽셀의 오차도 없다고 보장할 수 없습니다. 실기기의 마지막 확인은 남아 있습니다.

이 컴퓨터에서 다시 실행할 때, 터미널별로 다음을 실행합니다. 이미 실행 중인 Metro와 에뮬레이터는 그대로 사용하면 됩니다.

```sh
cd /Users/codexer/Promlive/storyloom
npm start -- --port 8081
```

```sh
/Users/codexer/Library/Android/sdk/emulator/emulator \
  -avd Promlive_S25_API36 -port 5564 -no-snapshot
```

```sh
cd /Users/codexer/Promlive/storyloom
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home \
ANDROID_HOME=/Users/codexer/Library/Android/sdk \
./android/gradlew -p android assembleDebug --console=plain
/Users/codexer/Library/Android/sdk/platform-tools/adb -s emulator-5564 install -r android/app/build/outputs/apk/debug/app-debug.apk
/Users/codexer/Library/Android/sdk/platform-tools/adb -s emulator-5564 reverse tcp:8081 tcp:8081
/Users/codexer/Library/Android/sdk/platform-tools/adb -s emulator-5564 shell am start -n com.storyloom/.MainActivity
```

프로필 등록은 `~/.android/avd/Promlive_S25_API36.ini`, 에뮬레이터 데이터는 `build/s25.avd`에 있습니다. 이 기기의 로컬 미리보기 설정이므로 Git에 포함하지 않습니다. 앱의 내부 패키지 ID `com.storyloom`은 저장 데이터의 연속성을 위해 유지했습니다.

## 입력바 치수

원본 사진의 너비 618을 기준으로 `화면 논리 너비 / 618` 배율을 적용합니다. 수치는 `src/features/chat/chatAppearance.ts`에 모았습니다. 하단 위치는 OS 안전 영역 위에 고정하며 입력이 길어지면 위로 늘어납니다.

| 항목 | 참고 사진 px | 1080px 에뮬레이터에서 확인 |
|---|---:|---:|
| 좌우 여백 | 20 | 각각 35px |
| 하단 여백 | 20 | 안전 영역 위 35px |
| 기본 높이 | 111 | 194px |
| 한 줄 입력 높이 | 171 | 299px |
| 두 줄 입력 높이 | 208 | 364px |
| 최대 높이 | 265 | 463px |
| 버튼 지름 | 70 | 약 122px |

최대 높이 이후에는 입력 내용이 내부에서 스크롤되고 확대 버튼으로 전체 입력창을 열 수 있습니다. 큰 시스템 글꼴에서는 읽을 수 있도록 높이가 달라질 수 있습니다. 웹과 모바일은 동일한 입력바·내역 컴포넌트를 공유하고, 실제 텍스트 입력만 각 플랫폼에 맞게 렌더링합니다.

입력바의 빈 상태·한 줄·여러 줄·최대 높이 사이에서는 목록과 설정에 쓰는 같은 스프링으로 높이와 모서리, 입력 위치, 버튼 위치가 함께 바뀝니다. 하단은 고정하고 위로 늘어나며, 입력을 연속해서 바꾸면 현재 크기에서 새 목표 크기로 이어집니다. 전송 버튼도 폭과 투명도를 함께 바꿔 나타나고 사라집니다. 텍스트 측정은 목표 입력 폭에서 수행해 애니메이션 중 불필요한 줄바꿈을 줄이고, 시스템의 동작 줄이기가 켜진 경우 즉시 전환합니다.

## 확인한 동작

- Android에서 빈 입력·한 줄·두 줄·최대 높이의 레이아웃과 위로 확장되는 동작.
- 키보드 열기·닫기 후 입력바 위치 복귀, 최대 높이 내부 스크롤.
- 전체 입력창에서 수정 후 접기, 짧아진 내용에 맞춘 축소.
- 전송 후 기본 높이 복귀, 새 채팅, 내역에서 이전 대화 열기.
- 작성 중 내용의 프로세스 재시작 후 복구.
- 웹 412 × 853 미리보기에서 한글 줄바꿈, 높이 제한, 내역 검색·재열기.

AI 인증·응답, 첨부, 음성 입력은 연결하지 않았습니다. 전송 버튼은 사용자 문장만 SQLite에 저장하며 화면에 `기기에만 저장됨`을 표시합니다. 첨부·음성 버튼은 미연결 안내를 표시합니다.
