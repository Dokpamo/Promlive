# 검증 기록

검증일: 2026-09-18. 실제 AI 호출·OAuth 인증 없이 수행했습니다. 기존 작업이나 메모리를 테스트 데이터로 사용하지 않았습니다.

2026-09-19 햅틱 추가 검증: Android Debug·Release 빌드 및 `npm run verify`가 통과했습니다. S25 크기 에뮬레이터의 `dumpsys vibrator_manager` 기록에서 스와이프 열기·닫기, 메뉴 열기·앞 화면 탭 닫기마다 `com.storyloom`의 `performHapticFeedback(constant=26)` 요청이 한 번씩 발생하는 것을 확인했습니다. 짧은 드래그를 취소한 두 경우에는 추가 요청이 없었습니다. 네이티브 재생 경로를 확인했으며 실제 S25의 체감 강도·길이는 미검증입니다. 햅틱은 현재 Android에만 연결했습니다.

## 채팅 UI 변경 검증

둥근 채팅 패널을 오른쪽으로 밀어 채팅 내역을 드러내는 전환으로 변경했습니다. Android S25 에뮬레이터에서 좌우 드래그, 짧은 드래그 취소, 빠른 스와이프, 세로 스크롤 후 열기, 메뉴·앞 화면 탭·뒤로가기를 확인했습니다. 입력창과 검색창 안의 가로 드래그가 페이지 이동을 일으키지 않으며 작성 중인 문장이 전환 후 유지됩니다. 검증용 초안은 확인 후 비웠습니다. 웹에서도 좌우 드래그, Escape 닫기, 검색과 채팅방 선택을 확인했습니다.

Android 모서리 반경 모듈은 API 31 이상에서 네 모서리 값을 읽습니다. 에뮬레이터의 시스템 반경은 모두 0이어서 기본 32dp로 표시됩니다. 실제 Samsung 기종별 곡률은 미검증입니다. iOS·macOS·Windows의 이번 전환 실행 검증과 모바일 웹의 실제 터치 검증은 별도입니다.

왼쪽 페이지 후속 변경에서는 Promlive 이름·검색바·채팅방 목록·하단 사용자 이름과 설정 버튼만 남겼습니다. Android S25 에뮬레이터에서 검색으로 목록을 좁히고 해당 채팅방을 여는 동작을 확인했습니다. 목록의 마지막 메시지가 채팅방별로 분리되고 빈 응답보다 마지막 실제 문장을 사용하는 것을 SQLite 테스트로 확인했습니다. 변경 후 Release 빌드와 `npm run verify`가 통과했습니다. 설정은 연결 전 버튼이며 사용자 이름은 임시 `사용자`입니다.

채팅 시작 화면과 왼쪽 내역으로 단순화한 현재 버전은 Android API 36의 새 `Promlive_S25_API36` 에뮬레이터에서 확인했습니다. 1080 × 2340 / 420dpi 기준 입력바 높이는 기본 194px, 한 줄 299px, 두 줄 364px, 최대 463px입니다. 키보드 열기·닫기, 확대 편집 후 축소, 로컬 메시지 저장, 새 채팅·내역 재열기, 작성 중 입력의 프로세스 재시작 복구를 확인했습니다.

Android 16의 키보드 겹침과 닫은 뒤 여백이 남는 현상을 수정했습니다. Metro의 기존 전체 `build` 디렉터리 제외 규칙이 의존성 `pretty-format/build`도 제외하는 문제를 앱 산출물 경로만 제외하도록 수정하여 Debug/Fast Refresh 실행을 복구했습니다.

변경 후 `assembleDebug`, `assembleRelease` 모두 성공했습니다. 실시간 공동 확인을 위해 에뮬레이터에는 Debug 앱을 설치한 상태로 두었습니다. 앱 크래시 로그는 없었습니다. [시작 화면](screenshots/android-s25-chat.png)과 [채팅 내역](screenshots/android-s25-history.png)을 저장했습니다.

웹 412 × 853에서 한글 입력, 최대 높이, 전송 후 초기 높이 복귀, 내역 검색·재열기를 확인했습니다. Samsung One UI·실기기 폰트·키보드의 픽셀 일치는 검증하지 않았습니다. [S25 화면 기록](S25_UI.md)에 치수와 재실행 방법이 있습니다.

아래 플랫폼별 표의 macOS·iOS·Windows 및 카드 기능은 **이전 UI**의 검증입니다. 새 채팅 UI의 모든 플랫폼 실행을 의미하지 않습니다.

## 자동 검사

`npm run verify` 성공: TypeScript 검사, Vitest **36개**, Vite 배포 빌드.

| 파일 | 개수 | 확인하는 위험 |
|---|---:|---|
| storage.test.ts | 13 | SQLite 재열기, 마이그레이션·롤백, SQL 바인딩, 수정 충돌, 초안·편집 버퍼, 재시작 복구, 오프라인 메시지의 순서·제목 및 AI 응답 미생성, 채팅방별 마지막 메시지 미리보기 |
| generation.test.ts | 11 | 응답 순서, 정상 완료, 부분 응답, 취소, 시간 초과, 중복 호출, 저장 실패, 조사 출처, 컨텍스트·페이지 분리 |
| creator.test.ts | 4 | SDK 형식, 실행별 권한, 요청량, ID 재사용, 실행 종료 후 권한 회수 |
| transport.test.ts | 3 | SSE 분할·CRLF, Grok 스트림 형식·완료·인증 참조, 비정상 종료 |
| workspace.test.ts | 1 | 저장 중 추가 편집 보존, 연속 저장 클릭 중복 억제, 재열기 후 저장 |
| drawer.test.ts | 4 | 짧은 드래그 복귀, 절반 이상 이동, 속도에 따른 방향 전환, 이동 범위 제한 |

저장 테스트는 메모리 객체 대체물이 아닌 Node의 실제 SQLite를 사용합니다. 네이티브 드라이버 전체 동작을 이 테스트로 대신 검증한 것은 아닙니다. AI 테스트는 `tests/helpers.ts`의 fixture와 테스트 전송을 사용하며 앱에는 포함하지 않습니다.

iOS·macOS 빌드에서는 RN/Hermes의 전역 변수 선언 및 빌드 스크립트 경고가 발생하지만 컴파일은 성공했습니다. 웹은 번들 약 531kB에 대한 Vite 크기 경고가 있습니다. 이 경고를 오류 없이 통과했다는 사실이 성능 목표를 달성했다는 뜻은 아닙니다.

화면 증거: [iOS 서재](screenshots/ios-library.jpg), [Android 재시작 후 저장 카드](screenshots/android-saved.png). Android 상태 표시줄의 밝은 배경·흰 아이콘 문제를 발견하여 어두운 아이콘으로 수정하고 다시 빌드·설치했습니다. iOS 텍스트 입력 도구는 한글 입력을 지원하지 않았고 영문 입력도 UI 변경을 확실히 입증하지 못해 입력 성공으로 기록하지 않았습니다.

## 로컬 빌드 산출물

- macOS: `build/macos/Build/Products/Release/storyloom.app`
- iOS 시뮬레이터: `build/ios/Build/Products/Release-iphonesimulator/Storyloom.app`
- Android: `android/app/build/outputs/apk/release/app-release.apk`
- Windows JS: `build/windows/index.windows.bundle`
- 웹: `dist/`

Android 패키지는 테스트용 debug 키로 서명되어 있습니다. Apple 앱은 로컬 unsigned/simulator 결과입니다. 스토어 배포·공증은 수행하지 않았습니다. `build/`, `dist/`, `Pods/`, 설치 패키지는 소스 관리에서 제외합니다.

## 다음 연결 단계에서 검증할 사항

1. Grok OAuth의 실제 지원 경로·범위·갱신 방식 확정과 OS 보안 저장소 연결. 현재 OAuth 구현은 없습니다.
2. 실제 AI 스트리밍·취소·시간 초과·네트워크 끊김·비용/모델 입력 한도를 네 플랫폼에서 검사.
3. 실제 검색 제공자와 출처 계약 연결. 현재 검색 결과를 만들어서 표시하지 않습니다.
4. Windows 환경에서 네이티브 빌드·실행 및 SQLite 저장·재시작을 확인한 뒤 버전 조합 확정.
5. 네이티브 WebView의 Worker·CSP·탐색·파일 접근 제한과 과도한 메모리 사용 대응 검증.
6. 큰 글꼴, 스크린 리더, 키보드 포커스·선택·복사, 가상 키보드, 회전·창 크기 변경을 플랫폼별 검증.
7. 긴 실제 대화의 Release 성능·메모리 측정. 현재 자동 테스트는 140개 메시지의 페이지·컨텍스트 무결성을 확인하며 성능 측정값은 없습니다.

이 항목들이 남아 있으므로 기획서 전체의 배포 완료를 주장하지 않습니다.
