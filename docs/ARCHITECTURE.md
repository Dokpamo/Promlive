# 구조와 데이터 보존

제품 기준은 `PRODUCT_SPEC.md`입니다. 기능을 수정할 때는 전체 구조보다 [기능 지도](FEATURE_MAP.md)에서 해당 책임과 테스트를 먼저 확인합니다.

후속 UI 요청으로 진입점을 채팅 화면으로 바꾸고 왼쪽 대화 내역만 노출합니다. 화면 치수의 기준은 [S25 UI](S25_UI.md)에 있습니다. 신규 설치의 샘플 카드 생성을 제거했으며, 일반 대화는 `promlive-general-chat` 내부 카드에 연결합니다. 기존 저장 데이터와 기능 모듈은 삭제하지 않습니다.

## 경계

```text
화면 → CardEditor / ConversationList / ChatSession / Notifications / SummaryExtensions
                               ↓ 필요한 저장 계약
app/Workspace → 기능 연결·화면 이동     SQLite / AI / 플랫폼 어댑터 ← app/runtime.ts
```

`src/ports/repository.ts`는 앱 조립용 합성 계약이며 기능에는 카드 편집·대화 관리·메시지 조회·설정별 작은 저장 계약을 전달합니다. `storage.ts`는 SQL 트랜잭션 계약, `ai.ts`는 생성 이벤트와 인증 저장 계약입니다. 상태·저장 로직은 네이티브 모듈에 의존하지 않습니다. SQL은 SQLite 어댑터에, xAI 응답 해석은 AI 어댑터에 있습니다.

## 영구 데이터

- 네이티브 iOS·Android·macOS: op-sqlite. Windows: `PromliveSqlite` C++ 모듈. 웹: sql.js와 IndexedDB.
- SQL은 파라미터 바인딩을 사용합니다. `SerialDatabase`가 쿼리와 짧은 트랜잭션을 직렬화하여 다른 호출의 쓰기가 트랜잭션에 섞이지 않도록 합니다.
- DB 버전 5, 카드 형식 1, 기본 템플릿 1, 코드 실행 형식 1, Creator SDK 1을 각각 관리합니다.
- 마이그레이션은 하나의 트랜잭션으로 적용합니다. 오류 시 롤백하고 기존 DB를 초기화하지 않습니다. 원본 보존과 이전 버전 업그레이드를 실제 SQLite 테스트로 확인합니다.
- 카드 본문, 대화, 메시지, AI 초안, 편집 버퍼, 설정은 별도 테이블입니다. 카드 JSON은 읽기·쓰기 경계에서 Zod로 검증합니다.
- 저장은 기대 `revision`을 조건으로 갱신합니다. 오래된 AI 초안이나 별도 편집의 변경으로 최신 내용을 덮어쓰지 않습니다.
- 편집 중 텍스트는 300ms 단위로 버퍼에 보관하고 화면 전환 시 flush합니다. 명시적 저장 중 새로 편집한 내용은 새 수정 번호를 기준으로 버퍼에 유지합니다. 강제 프로세스 종료 직전 아직 DB에 기록되지 않은 입력은 복구를 보장하지 않습니다.
- 즐겨찾기·보관 변경은 편집 버퍼와 함께 갱신합니다. 보관은 되돌릴 수 있고 UI에 영구 삭제 기능은 없습니다.
- 웹은 영속화에 실패하면 저장 성공을 표시하지 않고 해당 DB 세션의 후속 접근을 중단합니다. Web Locks로 같은 미리보기의 동시 탭 쓰기를 막습니다.

## 화면 상태와 비동기 완료

`ConversationList`는 대화 목록과 선택 ID를 소유하며 제목·미리보기는 최신 목록에서 읽습니다. 고정·이름 변경·삭제 후 조회도 이 객체가 처리합니다. 삭제는 생성 취소와 마지막 저장이 끝난 뒤 처리하며, 삭제 후 재조회에 실패하더라도 삭제된 행과 선택을 복원하지 않습니다. 목록 새로고침으로 메타데이터가 바뀌어도 대화 ID가 같으면 입력 복원을 다시 실행하지 않습니다. 겹쳐 실행된 새로고침에서는 늦게 도착한 이전 조회 결과를 버립니다.

`Workspace`에는 앱 조립·카드 목록·화면 이동을 남깁니다. 이동 요청마다 순서를 매겨 이전 카드 열기·새 채팅 생성·보관 작업이 늦게 끝나더라도 새 화면을 바꾸지 못하게 합니다. `WorkspaceChat`이 선택한 대화의 세션과 `MessageReader`를 `ChatScreen`에 전달합니다. 채팅 화면은 전체 Workspace/저장소 계약을 받지 않습니다. 상태의 주인은 다음과 같습니다.

- `CardEditor`: 카드 편집 값·수정 기준·복구 버퍼·AI 도우미 폼을 소유합니다. 버퍼 쓰기를 순서대로 실행하고 실패 후 재시도를 허용합니다. 저장 중 다시 열기는 저장·재기준화가 끝난 뒤 복구 버퍼를 읽습니다. 편집기와 도우미 화면은 이 객체를 직접 구독합니다.
- `ConversationList`: 목록 새로고침의 순서와 방 선택을 관리합니다. 겹친 새 방 요청을 합치고, 삭제가 끝날 때 사용자가 이미 다른 방을 골랐으면 그 선택을 유지합니다.
- `Notifications`: 오류·안내와 안내 ID를 소유합니다. 같은 문구를 다시 띄워도 타이머가 새로 시작되며, 이전 타이머는 새 안내나 오류를 지우지 않습니다. 알림 구독은 `NotificationToast` 안에 한정합니다.

- `useChatMessages`와 `MessageHistory`: 메시지·이전 기록 여부·조회 중 상태를 함께 관리합니다. 페이지 조회는 직렬화하고 중복 클릭은 하나로 합칩니다. 전송·스트리밍 전후 새로고침은 ID와 순서로 기존 범위에 합치므로 이미 불러온 기록을 버리지 않습니다. 40개를 표시하면서 한 개를 추가 조회해 이전 기록의 존재를 확인합니다.
- `ChatSession`: 대화별 초안 수정 버전과 접수·생성·취소 상태를 소유합니다. `Workspace.chats`가 보관하고 화면은 `useChatSession`으로 구독합니다. 화면을 떠나도 전송 완료는 원래 방에 반영되며, 새 편집은 지우지 않습니다.
- `sessionStore`: 메시지 삽입·전송 ID 기록·해당 초안 버전의 수락을 한 트랜잭션으로 처리합니다. `accepted_revision`은 빈 초안에도 남기므로 늦은 저장이 이미 보낸 내용을 복원하지 못합니다. 같은 ID/내용의 재접수는 기존 메시지를 반환하며 AI를 다시 호출하지 않습니다.
- 입력창 버튼은 `composerAction`의 한 상태를 사용합니다. 생성 Promise가 끝나지 않아도 중단 버튼은 활성화됩니다. 전송 완료의 목록 갱신은 대화 목록만 읽고 카드 전체는 다시 읽지 않습니다.

`CardEditor`의 카드 저장과 초안 적용은 같은 완료 처리 규칙을 사용합니다. 작업을 시작한 편집 세션이 여전히 열려 있으면 그동안 수정한 필드를 보존하고 새 저장 리비전 위에 합쳐 버퍼에 기록합니다. 다른 편집 세션이 열렸으면 이전 작업이 현재 편집기를 교체하지 않습니다.

## 공통 UI

`layout/RowPressable`과 `PressSurface`가 행·버튼 눌림을, `panelGeometry`와 `metrics`가 패널/하이라이트 곡률·상단 규격을 소유합니다. `SwipeBackModal`, `sheetMotion`, `panelAnimation`, `DragClickBoundary`는 설정과 채팅의 공통 제스처 기반입니다. 설정만의 행 구성과 채팅 목록·입력창의 제스처 정책은 각 기능에 남깁니다. 이번 분리는 기존 치수·색상·스프링·블러 표시 규칙을 바꾸지 않습니다.

## 생성과 채팅

`GenerationCoordinator`가 작성·조사·채팅·Creator 요청을 공통 처리합니다. 동시 2개, 기본 120초, 응답 30,000자, 출처 30개를 제한합니다. 자동 재시도는 없고 요청 ID를 재사용하지 않습니다. 채팅 전송 ID는 DB에서 멱등 처리하고 서로 다른 내용으로 재사용하면 거부합니다.

제공자의 명시적 `done` 이벤트만 정상 완료로 간주합니다. EOF·오류·취소는 부분 결과와 해당 상태를 남깁니다. 종료된 작업은 AbortSignal을 통해 연결을 정리하며, 앱 재시작 시 미완료 작업을 중단 상태로 전환합니다.

`CreationService`는 UI 수명과 독립적입니다. 중간 응답은 최대 약 20회/초로 화면에 게시하고 약 700ms마다 저장합니다. 종료 상태는 즉시 저장합니다. 저장 실패를 완료로 표시하지 않습니다. AI 초안은 생성 시작 시점의 카드 수정 번호를 보유합니다.

화면은 최근 40개 메시지씩 조회하고 가상 목록으로 렌더링합니다. AI 컨텍스트는 별도로 최근 최대 200개를 조회하여 문자 수 예산으로 자릅니다. 전송 범위와 제외된 메시지를 표시합니다. 200개보다 오래된 기록은 전송에서 제외되지만 DB에 남습니다.

작성 중 메시지는 생성이 수락되어 DB에 기록된 뒤 비워집니다. 응답을 기다리며 작성한 다음 메시지는 기존 요청이 끝나도 지우지 않습니다.

제공자가 연결되지 않으면 같은 접수 계약으로 사용자 문장만 로컬 저장합니다. 이때도 전송 ID와 초안 버전 보장을 유지하며, 응답 행이나 네트워크 요청은 만들지 않습니다.

## 제공자와 인증

앱의 `SelectedProvider`는 설정에 저장한 xAI API 연결과 대화 모델을 `GrokProvider`에 연결합니다. 모델과 키는 요청 시작 시 캡처하고 주소는 호스트의 공식 xAI 주소로 고정합니다. 키 저장을 기다린 뒤 저장된 값과 일치하는지 확인하므로 저장 실패 시 예전 키로 요청하지 않습니다. 제공자의 오류 본문은 인증·한도·모델 오류 분류에만 쓰고, 화면과 로그에는 로컬 안내문만 노출합니다. 다른 제공자의 실제 생성 어댑터, OAuth 로그인·갱신, 검색 도구, 모델별 세부 API 매개변수 연결은 후속 범위입니다. 설정 UI에 나타난다는 것만으로 해당 생성 기능이 구현되었다는 뜻은 아닙니다.

`AiSettingsPreferences`는 비밀값을 제외한 설정과 `CredentialStore`의 API 키를 합쳐 설정 화면에 제공합니다. 키는 프로바이더·연결 방식별로 분리하고, 입력·수정·삭제를 순서대로 저장하며 다음 실행에 복원합니다. 일반 설정 DB·모델 캐시·코드 카드에는 키를 전달하지 않습니다. 네이티브는 OS 인증 저장소, 웹은 별도 IndexedDB의 AES-GCM 암호문과 추출 불가능한 로컬 CryptoKey를 사용합니다. 웹 저장소는 같은 출처에서 실행되는 앱 코드가 접근할 수 있으며 OS 키체인과 동일한 보호를 제공하지 않습니다. 참고한 [xAI 추론 API 문서](https://docs.x.ai/developers/rest-api-reference/inference)는 API 키 기반 Bearer 인증을 설명하며 사용자 OAuth 지원 여부를 대신 입증하지 않습니다.

## 첫 개인 확장

`SummaryExtensions`는 대화 요약 한 종류만 실행합니다. AI에는 `summaryProgram`의 작은 JSON 계약과 이전 확장 문서만 보내고 앱 소스·대화·키를 보내지 않습니다. 읽기 → 생성 → 자체 저장의 세 단계만 허용하며 임의 JavaScript, 네트워크 주소, DB 질의, 메시지 수정은 표현할 수 없습니다. 기존 `CreatorHost`와 생성 제한을 재사용합니다. 범용 SDK·렌더러·레이아웃 교체 지점은 아직 공개하지 않습니다.

새 버전은 불변 문서로 저장하며 초안/활성 포인터를 분리합니다. 권한을 확인하고 적용해야 버튼이 나타납니다. 실행 범위는 클릭한 대화 ID에 고정하고, 비활성화·복원 시 실행 권한을 회수하고 진행 중 호출을 취소합니다. 실행 리비전을 결과 저장 트랜잭션에서도 확인하므로 늦은 결과를 저장하지 않습니다. 새 초안을 만드는 것만으로 기존 활성 실행의 권한을 회수하지는 않습니다.

요약 결과는 방별 별도 테이블에 저장합니다. 코드 복원은 이미 저장한 요약을 삭제하지 않으며, 대화를 삭제하면 해당 방 요약만 함께 지웁니다. 자세한 제한과 흐름은 [요약 확장](SUMMARY_EXTENSION.md)에 있습니다.

## 플랫폼과 빌드

Metro는 플랫폼별로 React Native 구현체를 선택합니다. Vite 미리보기는 React Native Web과 웹 저장 어댑터를 사용합니다. iOS는 [Apple의 Scene 수명 주기 지침](https://developer.apple.com/documentation/uikit/transitioning-to-the-uikit-scene-based-life-cycle)에 따라 SceneDelegate에서 화면을 시작합니다.

이 구조가 네 플랫폼에서 동일하게 검증된 것은 아닙니다. 정확한 확인 범위는 `VERIFICATION.md`에 기록합니다.
