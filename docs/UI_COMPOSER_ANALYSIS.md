# 기존 채팅 입력바 분석과 새 UI 적용

> 이 문서는 첫 번째 입력바 구현의 조사 기록이다. 2026-10-01 사용자의 초기화 요청과 “빈 상태부터 두 단” 지시에 따라 그 구현은 제거했다. 현재 구현과 검증은 [새 입력바 구조](UI_CHAT_INPUT.md)를 따른다. 아래의 한 줄/두 단 전환, 전체 화면 작성, 커서 복원 상태 머신은 현재 앱에 연결되지 않는다.

2026-10-01. 사용자의 요청: 기존 입력바의 기능과 전환을 자세히 분석해 새 UI에 적용하고, 입력바의 기기 모서리 곡률 보정은 제거한다. 사진의 입력바 높이와 ‘대화 시작’ 버튼을 실제 치수로 대조한다.

## 사진에서 확인할 수 있는 것

입력바 참고는 `photo_6188107052819878826_y.jpg`~`8828_y.jpg`, 버튼 참고는 `photo_6188107052819878842_y.jpg`다. 모두 618×1280px이며, 파일 픽셀을 측정했다. 스크린샷만으로 OS의 실제 dp, 입력 전환 애니메이션이나 선택 복원 동작을 알 수는 없다. 아래 dp는 프로젝트의 기존 412dp 기준 환산값이다.

| 대상 | 사진 측정/설계값 | 수정 전 새 UI | 이번 적용, 412dp 기준 |
|---|---|---|---|
| 기본 입력바 | 중앙부 y=1187…1262, 높이 76px | 높이 56dp | 50.67dp |
| 입력바 둥근 끝 | 높이 절반 | 28dp | 25.33dp |
| 큰 하단 버튼 | 중앙부 약 89px, 설계값 90px | 높이 54dp | 60dp |
| 큰 버튼 모서리 | 약 32px | 16dp | 21.33dp |
| 큰 버튼 좌우 간격 | 약 27~28px | 공통 28 reference px | 기존 공통값 18.67dp 유지 |

이미지의 입력바는 플러스가 별도 원으로 분리되어 있지만, 사용자가 요청한 대로 새 입력바는 플러스를 내부에 합친다. 원본 전송 버튼의 늘어진 가로형 대신 요청한 정원을 유지한다. 최신 이미지의 회색 기본 버튼은 로딩 상태로 보이며, 앱의 활성 ‘대화 시작’은 공통 selectedBackground/selectedForeground를 사용한다. 사진 전체의 두 버튼/가입 안내를 복제하는 작업은 아니다.

## 분석한 코드

- `src/features/chat/ChatComposer.tsx`, `ExpandedComposer.tsx`: 입력 상태, 측정·최대 줄 수, 도구 표시, 초점·선택·스크롤 반환.
- `ComposerInput.tsx`, `ComposerInput.web.tsx`, `useComposerLayoutFrame.ts`, `composerGeometry.ts`: 네이티브/웹 입력 측정과 애니메이션 프레임.
- `src/layout/KeyboardMotion.tsx`, `.android.tsx`, `focusWithKeyboard.ts`: 플랫폼 키보드 신호와 포커스 인계.
- `SheetScrollView.touch.tsx`, `SheetTextInput.touch.tsx`, `editorScroll.ts`, `useBlankDismiss.ts`: 선택과 스크롤 경합, 읽던 위치, 빈 영역 닫기.
- Android `KeyboardMotionPackage.kt`, `KeyboardInsetMotion.kt`, `EditorCaretVisibility.kt`: IME 프레임 동기화, Fabric 측정 좌표, 커서 노출, 전체 화면 확장 준비.
- 기존 `tests/composer-motion.test.tsx`, `keyboard-editor-focus.test.ts`: 전환 과정에서 유지해야 하는 동작.

## 입력 상태와 전환

| 상태 | 기존 동작 | 새 UI 적용 |
|---|---|---|
| 비어 있고 초점 없음 | 낮은 바, 플러스, 안내 문구 | 사진 비율의 50.67dp 기본 높이 |
| 초점 있음/한 줄 작성 | 위쪽 텍스트·아래쪽 도구 행으로 확장 | 동일한 구조, 새 색상·아이콘 |
| 2~7줄 | 내용 높이에 따라 바가 증가, 확장 버튼 표시 | 동일 |
| 7줄 초과 | 바 크기 제한, 입력 내부 스크롤 | 동일, 선택 제스처 우선 |
| 공백뿐인 입력 | 전송 숨김 | 동일 |
| 보낼 글/첨부 있음 | 전송 표시 | 별도 등장 애니메이션 없이 즉시 표시 |
| 전체 화면 작성 | 기존 입력칸은 유지, 다른 작성 화면이 올라옴 | 동일한 텍스트 폭으로 별도 화면 표시 |
| 작성 중 키보드 닫음 | 글이 있으면 바 유지, 빈 바는 접기 | 동일 |
| 전체 화면 전송 | 한 번 전송하고 기본 입력으로 복귀 | 로컬 대화에 한 번 추가, 초안 초기화 |

바의 높이와 도구 위치는 같은 애니메이션 프레임을 사용한다. 텍스트 영역에는 새 글에 필요한 최종 높이를 즉시 주고 외곽 바만 따라오게 한다. OS 동작 줄이기가 켜져 있으면 이동을 생략한다. 기본 상태의 사진 높이와 작성 중의 가변 높이는 구분한다.

## 펼쳤다가 접을 때 보존하는 정보

1. 초안은 하나의 `ScreenMemory` 값을 사용한다. 기본 입력과 전체 화면 입력은 같은 내용을 읽는다.
2. 펼치기 전에 선택 시작/끝과 내부 스크롤 위치를 기억한다. 긴 글 끝에 커서가 있더라도 사용자가 앞부분을 읽고 있었다면 읽던 위치가 우선이다.
3. 전체 화면에서 글이 모두 보이더라도 원래 기본 입력의 스크롤값을 버리지 않는다.
4. 전체 화면에서 직접 스크롤·편집·선택을 바꾸면 바뀐 위치를 반환한다. 글을 줄였으면 유효 범위로 제한한다.
5. 접을 때 기본 입력으로 먼저 초점을 반환하고, 퇴장 애니메이션이 끝난 뒤 전체 화면 입력을 제거한다. Fabric이 제거 시 초점을 잃을 수 있어 다음 프레임에 한 번 확인한다.
6. 그 사이 사용자가 새로 스크롤하거나 입력하면 이전 복원 요청은 취소한다. 이미 닫힌 작성 화면의 늦은 키보드 응답은 새 화면에 영향을 주지 않는다.

## 키보드와 입력 제스처

Android는 `keyboardDidShow`를 받은 뒤 위치를 바꾸는 방식으로는 이동이 늦다. 이미 프로젝트에 있는 네이티브 IME 브리지를 재사용해 OS 진행 프레임으로 움직이고, 그 좌표를 Fabric에도 반영해 이동한 버튼의 터치 판정이 일치하게 한다. 전체 화면 진입 준비 신호는 포커스보다 먼저 등록한다. 기존 UI나 AI 서비스는 연결하지 않는다.

iOS는 키보드 프레임과 애니메이션 시간을 사용한다. 실제 시뮬레이터에서 고정 크기 입력에 내용 높이 이벤트가 오지 않는 경우를 확인했다. RN 0.81 Fabric의 `RCTTextInputComponentView.mm`는 레이아웃 갱신에서 해당 이벤트를 내보낸다. 새 구현은 동일한 글꼴·폭으로 텍스트 줄 배치를 별도로 측정해 높이를 갱신한다. 입력 커서는 해당 줄의 위치로 계산해 보이는 범위 안으로 이동시키되, 읽던 위치 복원 중에는 이를 억제한다.

입력칸에는 별도 네이티브 터치 핸들러를 중첩하지 않는다. 입력과 스크롤이 이미 공유하는 제스처의 ref를 뒤로가기와 연결한다. 버튼 전체에 터치 보호를 걸면 확장·전송을 막을 수 있으므로 보호 범위는 입력이다. 기존 선택 범위가 있을 때는 선택 핸들을 유지하고, 세로 스크롤 시작만 입력의 지연된 길게 누르기를 취소한다. 가로 커서 이동은 입력 제스처를 유지해 페이지 뒤로가기로 넘어가지 않는다.

Android에서는 전체 화면 입력을 제거한 뒤 RN의 JS 초점 기록과 실제 OS 입력 대상이 달라져, 대화방을 나가도 키보드가 남는 경우를 재현했다. 대화방 닫기와 첨부 열기에서 JS 키보드 닫기와 함께 기존 네이티브 브리지의 명시적 닫기를 호출한다. 대기 중인 포커스 요청을 무효화하고 실제 초점과 IME를 닫는다. 재빌드 후 전체 화면 펼치기→접기→대화방 나가기 순서에서 `mInputShown=false`와 `mImeWindowVis=0`, 상세 버튼의 정상 재진입을 확인했다.

전체 화면은 텍스트·버튼에서 시작한 동작으로 닫히지 않는다. 빈 영역의 아래 방향 드래그만 닫기 후보가 되고, Android 뒤로가기와 웹 Escape도 지원한다. Android에서 키보드가 먼저 뒤로가기를 소비하면 먼저 키보드가 닫히고, 다음 뒤로가기가 작성 화면을 접는다.

## 여백과 연결 범위

기기 하단 모서리 반지름은 입력바 계산에서 사용하지 않는다. 좌우는 `20 × scale`, 하단은 `safeBottom + 20 × scale`이다. 키보드 위에서는 안전 영역 중복분을 빼 동일 간격을 유지한다. 바 자체의 둥근 모양과 다른 페이지의 모서리 전환은 각각 별도다.

전송·첨부는 새 UI의 로컬 대화/번들 갤러리 범위다. 기존 생성 중단, 모델 선택, 도구 실행, 사진 앱 접근, 서버 응답은 연결하지 않았다. 기능이 연결되지 않은 전송 중단 버튼이나 가짜 AI 답변을 표시하지 않는다.

관련 구현은 모두 `src/ui/` 안에 두고 `ui-boundary` 테스트로 이전 UI import가 연결되지 않는지 검사한다. 실제 앱 동작과 검증 항목은 [채팅방 문서](UI_CHAT_ROOM.md)에 기록한다.
