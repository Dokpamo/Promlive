# 서재 카드 상세

2026-09-30. ‘원본 비율 · 전체 폭’ 시안을 `src/ui/CardDetail.tsx`로 연결한다. 기존 화면이나 서비스를 다시 불러오지 않는다.

## 이미지와 독립 버튼

- 상단바와 ‘카드 정보’ 제목은 없다. 표지는 화면 맨 위에서 시작해 OS 시계·배터리 뒤까지 이어진다. Android/iOS 상태 표시줄은 표시한 채 배경만 그 아래로 그린다.
- 표지 높이는 `화면 폭 / 원본 가로세로 비율`이다. 늘이거나 추가로 크롭하지 않는다. 도서관 표지는 3:4이며 다른 초기 아틀라스 타일은 원본 정사각형 전체를 표시한다.
- 뒤로가기와 메뉴는 본문 ScrollView 밖의 개별 버튼이다. 투명한 가로 바나 전체 폭의 터치 영역을 덧대지 않는다. 본문의 끝부분 탄성도 버튼에 전달하지 않는다.
- `NavigationButton`, `navigationActionMetrics`, `Icon`, `colors`를 공통 헤더·편집 화면과 함께 사용한다. 412dp에서 아이콘 프레임 29.33dp, 터치 영역 48dp, 안전 영역 아래 8dp다. 이미지의 위쪽 여백만 제거하고 버튼·메뉴는 상태 표시줄 아래의 기존 위치를 유지한다. 더 작은 화면에서는 기존 `navigationScale`로 아이콘을 줄이고 터치 영역은 최소 48dp를 유지한다.
- 왼쪽은 기존 내부 화면의 8dp, 오른쪽은 공통 `actionInset × scale`이다. 412dp 기준 오른쪽 여백은 10.67dp다. 버튼 색과 작은 원형 바탕은 `foreground`와 `background`다.
- 뒤로가기 SVG는 기존 `back`을 그대로 사용한다. 메뉴의 점 세 개는 공용 32단위 아이콘 세트에 `more`로 추가했다. 별도 라이브러리 아이콘을 섞지 않는다.
- 이미지 아래에는 전체 제목·제작자·태그·소개·갤러리·인트로·선택 가이드를 표시한다. 아래 대화 시작 영역은 고정하며 OS 하단 안전 영역을 확보한다.

## 대표 이미지 감상 — 2026-10-01

- 대표 이미지를 누르면 공통 오른쪽 진입 전환으로 `ImageViewer`를 연다. 제목·제작자·본문·대화 시작·하단 탭은 이미지 화면에 표시하지 않는다.
- 공통 다크 팔레트의 배경 `#101010`을 사용한다. 이미지는 화면 가로·세로 안에 원본 전체가 들어오도록 중앙 정렬하며, 남는 공간은 같은 배경으로 채운다. 3:4 표지와 정사각형 아틀라스 타일 모두 추가 크롭·변형 없이 표시한다.
- 뒤로가기와 확대 버튼은 기존 `NavigationButton` 크기·위치를 재사용하고 다크 팔레트의 밝은 아이콘을 사용한다. 시계·배터리와 Android 하단 제스처 표시도 밝은 색으로 바꿨다가 복귀 시 원래 색으로 되돌린다.
- 두 손가락으로 1~4배 확대·축소하고 확대 상태에서는 한 손가락으로 이미지를 이동한다. 두 번 누르기와 확대 버튼은 2.5배 확대 / 전체 보기로 전환한다. 웹·데스크톱은 두 번 클릭과 드래그도 지원한다.
- 원래 크기에서는 공통 오른쪽 스와이프로 상세에 돌아온다. 확대·핀치 중에는 뒤로가기 제스처를 막아 이미지 이동과 충돌하지 않게 한다. 상단 버튼과 Android 시스템 뒤로가기는 확대 상태에서도 이미지 화면만 닫는다.
- 상세 화면은 바로 아래 레이어에 유지하므로 돌아와도 본문 스크롤 위치가 유지된다. `ScreenMemory.view.coverOpen`으로 열린 이미지 화면을 복원하며, 복원 첫 렌더에는 진입 애니메이션이 없다. 이미지 확대·이동은 새 진입과 화면 크기 변경 시 전체 보기로 초기화한다. 유효한 완료본 상세가 없거나 편집 중이면 이미지 화면을 복원하지 않는다.

구현: `ImageViewer`, `ImageSurface`의 네이티브/웹 어댑터, `useImageTransform`, `imageViewport`. 네이티브의 핀치 배율·드래그 좌표는 Animated 네이티브 이벤트로 연결하며 매 프레임 React를 다시 그리지 않는다.

## 연결과 복원

- 서재의 완료본을 누르면 상세를 연다. 작성 중 초안을 상세에 섞지 않는다.
- 메뉴의 ‘생성에서 편집’은 새 UI의 `CardEditor`로 연결한다. 돌아오면 상세를 다시 보여주며, 완료 전에는 기존 표시본을 유지하고 완료 후에만 새 내용을 반영한다.
- 뒤로가면 서재의 검색·분류·스크롤 위치를 유지한다. Android 뒤로가기에서는 열린 메뉴를 먼저 닫고, 그다음 상세를 닫는다.
- 본문 어디서든 오른쪽으로 밀어 뒤로갈 수 있다. 짧으면 복귀하고, 열린 메뉴와 편집 입력칸은 각 조작을 우선한다. [공통 제스처](UI_GESTURES.md)를 따른다.
- 네이티브에서는 상세·편집 뒤에 가려진 화면도 같은 크기의 레이어로 유지한다. `display: none`으로 목록 높이가 0이 되어 가시 항목 보정이 스크롤을 바꾸는 것을 막는다. 숨긴 화면은 투명도·터치·접근성만 비활성화하고, 웹은 키보드 포커스를 막기 위해 `display: none`을 유지한다.
- 공통 `ScreenMemory`에 `detailCardId`와 `detail` 스크롤 위치를 저장한다. 재실행 첫 렌더에서 복원하며, 이전 버전의 저장 문서도 계속 읽는다. 삭제되거나 완료본이 없는 카드는 복원하지 않는다.
- ‘대화 시작’ 버튼은 `photo_6188107052819878842_y.jpg`의 하단 버튼 형태를 기준으로 높이 90, 반지름 32(reference px)를 적용한다. 412dp에서는 높이 60dp·반지름 21.33dp, 좌우는 기존 공통 28 reference px다. 선택 배경·글자색은 앱 공통 팔레트를 사용한다.
- ‘대화 시작’은 같은 카드의 새 UI 채팅방을 연다. 기존 대화가 있으면 이어서 열고, 없으면 카드 인트로로 로컬 대화를 시작한다. 돌아오면 상세 위치를 유지한다. 실제 AI 서비스는 연결하지 않았다. [채팅방 구조](UI_CHAT_ROOM.md)를 따른다.

## 공개 항목과 도서관 예시 — 2026-10-01

제목·제작자·태그·소개·갤러리·인트로는 필수이고 가이드는 선택이다. 생성 화면의 편집기도 이 항목을 저장하며, 필수 항목이 비어 있으면 완료를 막고 빠진 항목을 알려 준다. 태그는 쉼표로 입력하고, 갤러리는 현재 번들 이미지에서 최소 한 장을 선택한다. OS 사진 보관함 가져오기는 아직 연결하지 않았다.

‘별이 머무는 도서관’에 사서 서율과 제작자 별담, 네 가지 태그, 소개 두 문단, 시작 장면, 선택 가이드를 채웠다. 갤러리에는 기존 세로 표지와 새로 만든 가로 장면 두 장을 넣었다. 예전 저장 문서도 새 필드를 보충하되 사용자가 직접 편집한 소개·인트로는 덮어쓰지 않는다. 초안과 완료본 분리는 그대로 유지한다.

갤러리 배치·이미지 생성 기록·출처는 [UI_GALLERY.md](UI_GALLERY.md)를 참고한다.

## 검증

화면 테스트에서 상세 열기·메뉴 닫기·편집 왕복·완료본 유지와 갱신·서재 위치 보존·재실행 복원을 확인한다. 화면 저장소 테스트에서는 예전 문서 호환과 완료되지 않은 카드의 상세 복원 차단을 확인한다.

적용 후 TypeScript, 관련 6개 파일·39개 테스트, 웹 빌드를 통과했다. 412px·360px 웹 화면에서 공용 버튼 크기·축소 규칙과 표지 비율을 측정했고 가로 넘침이 없었다. 기존 웹 번들의 대용량 경고는 유지된다.

Android 1080×2340 에뮬레이터에서 상세 표지는 `[0,63]–[1080,1503]`으로 3:4다. 메뉴 버튼 `[926,84]–[1052,210]`은 기존 상단 오른쪽 버튼과 같고, 뒤로가기 `[21,84]–[147,210]`은 편집 화면과 같다. 편집 왕복·본문 스크롤 중 버튼 고정·프로세스 재시작 후 열린 상세와 스크롤 위치 복원·서재 복귀를 확인했다. iOS/macOS/Windows 네이티브 실행은 이번 변경에서 별도 검증하지 않았다.

### 상태 표시줄 뒤까지 확장 — 2026-10-01

사용자 결정: OS의 시계·배터리를 표시한 채 이미지나 앱 배경이 그 뒤까지 이어지게 한다. 상세 표지는 `SwipeBack.drawBehindStatusBar`를 사용해 위쪽 안전 여백을 생략하고, 버튼과 메뉴에만 기존 안전 여백을 더한다. iOS ScrollView의 자동 콘텐츠 인셋을 끄므로 시스템이 표지를 다시 아래로 밀지 않는다. 편집 화면의 입력창과 헤더는 기존 안전 영역을 유지한다.

Android 표지는 이제 `[0,0]–[1080,1440]`으로, 3:4 비율을 유지하면서 상단 63px까지 이어진다. 뒤로가기 `[21,84]–[147,210]`, 메뉴 버튼 `[926,84]–[1052,210]`은 전과 같다. iPhone 17 Pro / iOS 26.5에서도 시계·배터리 아래까지 표지가 이어지는 화면을 확인했다. 두 플랫폼에서 재실행·상세 복귀·재진입을 확인했으며 Android 메뉴 위치도 확인했다. 새 프로세스의 런타임 오류는 없다. TypeScript, 관련 18개 테스트, 웹 빌드가 통과했다.

### 이미지 감상 검증 — 2026-10-01

TypeScript, 관련 5개 파일·37개 테스트, 웹 빌드를 통과했다. 테스트는 이미지 비율·확대 한계·이동 범위, 감상 화면 진입과 복귀, 확대 중 뒤로가기 차단, 상세 스크롤 유지, 유효한 이미지 화면의 재실행 복원과 삭제된 카드의 복원 차단을 확인한다.

Android 1080×2340에서 전체 보기 이미지는 `[0,450]–[1080,1890]`으로 원본 3:4를 유지한다. 기존 버튼 위치를 유지하면서 확대 버튼·이미지 이동·전체 보기 복원·오른쪽 스와이프·시스템 뒤로가기를 확인했고 앱 런타임 오류는 없었다. iPhone 17 Pro / iOS 26.5에서도 이미지 진입·버튼 확대·이동·원래 크기 복원·상세 복귀와 밝은 상태 표시줄을 확인했다.

네이티브 두 손가락 핀치는 구현했지만 이번 자동화 환경에서 실제 다중 터치 입력은 검증하지 못했다. Android 임시 입력 도구 실행이 종료되어 해당 결과를 앱 검증으로 계산하지 않았다. 웹은 화면 테스트와 빌드를 확인했으며 실제 터치 브라우저의 핀치는 별도 확인 대상이다.
