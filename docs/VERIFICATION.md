- 선택창을 해당 설정 페이지의 윈도우 안에 표시하고, 퇴장을 시작할 때 터치 점유를 넘깁니다.
  긴 선택창은 내려가는 중 손가락과의 상대 위치 변화 때문에 Android ScrollView가 새 스크롤을
  시작해 페이지의 제스처를 취소하기도 했습니다. 퇴장 애니메이션 전에 네이티브 스크롤을 끄고,
  이어서 잡은 페이지 제스처를 보호합니다. 평상시 목록 스크롤의 우선순위는 유지합니다.
- 닫히는 동안 같은 선택창이나 다른 선택창을 다시 열면 새 인스턴스로 표시하고, 이전 닫기 완료
  콜백이 새 창을 없애지 않도록 구분합니다. Android 뒤로가기는 열린 선택창부터 닫습니다.
- 최신 Debug 앱을 새로 실행해 라이트 재선택·한국어 재선택 직후 첫 스와이프, 프로바이더 재선택
  직후 첫 스와이프 4회 연속, 프로바이더 목록 끝까지 스크롤, 선택창 퇴장 중 Android 뒤로가기
  연속 입력을 확인했습니다. 현재 프로세스의 JavaScript·Android 런타임 오류는 없었습니다.
  기존 테마·언어·프로바이더 값을 유지했습니다.
- 관련 테스트 38개, TypeScript, 웹 배포 빌드가 통과했습니다. 테스트에는 퇴장 완료 전 입력 전달,
  닫힌 스크롤 영역의 터치 해제, 네이티브 스크롤 중지와 퇴장 시작 순서, 빠른 재열기의 오래된

## 2026-09-22 채팅내역 관리 팝업

- 검색과 생성 버튼은 후속 요청에 따라 팝업 밖 원래 위치로 되돌렸습니다. 카드 목록/채팅내역에 따라
  검색·생성 대상이 바뀌고, 팝업은 검색바 아래에서 시작합니다. 기존 목록과 설정의 색상,
  곡률 비율, 눌림 효과를 재사용합니다. 길게 누르면 선택·고정/해제·이름 변경·삭제 메뉴가 열립니다.
- SQLite v3로 고정 시각과 직접 수정한 제목 여부를 보존합니다. 삭제는 메시지·초안을 함께 지우며,
  생성 중인 응답의 취소가 끝난 뒤 실행합니다. 삭제 후 늦게 저장되는 입력 초안은 다시 만들지 않습니다.
- 관련 자동 테스트 43개 통과: 이전 DB 마이그레이션, 재실행 후 고정/제목 유지, 생성 취소와 삭제,
  다중 선택·검색 후 선택 유지·선택한 항목만 삭제, 기존 채팅/저장 회귀 테스트를 확인했습니다.
- TypeScript, 웹 배포 빌드, Android 배포 JS 번들이 통과했습니다. S25 에뮬레이터의 최신 Debug 앱에서
  길게 누르기·메뉴·이름 변경·고정 구분선·다중 선택을 확인했습니다. 테스트용 채팅 13개만 선택해 삭제했고,
  기존 채팅은 유지했습니다. 스크롤 끝에서 마지막 항목과 삭제 버튼 사이에 28 물리 픽셀 여백을 확인했습니다.
- 전체 테스트에는 아래 기록의 기존 xAI OAuth 기대값 실패 1개가 남아 있습니다.

- 웹 배포 빌드와 Windows용 JS 번들이 통과했습니다. Windows 네이티브 빌드·실행은 확인하지 않았습니다.

  로그인 미리보기 UI와 기대값이 달라 실패합니다. 변경 전 커밋 `125e7aa`의 동일 테스트에서도 실패를 재현했습니다.

## 2026-09-20 상태 관리 회귀 검증

Node 26.0.0에서 `npm run verify`가 통과했습니다. 수정 전에 화면 테스트로 제목 메타데이터 변경에 따른 입력 재조회, 41개 연속 전송 후 40개만 보이는 현상, 이전 기록을 읽은 뒤 전송하면 40개로 줄어드는 현상을 확인했습니다. 편집 테스트로 선택 대화의 오래된 제목과 초안 적용 완료 시 새 편집·다른 카드 편집기를 덮어쓰는 문제도 재현했습니다. 해당 테스트는 수정 후 모두 통과했습니다.

실제 SQLite와 React `ChatScreen`을 사용해 방 전환·늦은 입력 복원·저장 중 추가 입력·실패 시 입력 보존·스트리밍 중 제목 갱신도 확인했습니다. 화면 테스트의 React Native 위젯과 입력 컴포넌트는 DOM 대체물을 사용하므로 네이티브 렌더링이나 제스처 검증을 뜻하지 않습니다. 브라우저의 기존 채팅에서는 임시 초안이 새로고침 후 복원되는 것을 확인하고 비웠으며, 새 메시지는 전송하지 않았습니다.

[GitHub Actions 설정](../.github/workflows/verify.yml)은 Node 22·24에서 `npm ci`와 `npm run verify`를 실행하도록 추가했습니다. 저장소에 반영되면 main 푸시와 PR에서 실행됩니다. 이 기록의 실행 결과는 로컬 검사이며 GitHub Actions 원격 실행 결과는 아닙니다.

웹의 DB 전체 스냅샷 저장 방식은 이번 변경 범위에 포함하지 않았습니다. DB 크기별 지연·메모리 측정과 저장 방식 이전은 별도 작업이며 이번 상태 관리 수정이 웹 저장 성능을 개선했다고 주장하지 않습니다.

## 채팅 UI 변경 검증

둥근 채팅 패널을 오른쪽으로 밀어 채팅 내역을 드러내는 전환으로 변경했습니다. Android S25 에뮬레이터에서 좌우 드래그, 짧은 드래그 취소, 빠른 스와이프, 세로 스크롤 후 열기, 메뉴·앞 화면 탭·뒤로가기를 확인했습니다. 입력창과 검색창 안의 가로 드래그가 페이지 이동을 일으키지 않으며 작성 중인 문장이 전환 후 유지됩니다. 검증용 초안은 확인 후 비웠습니다. 웹에서도 좌우 드래그, Escape 닫기, 검색과 채팅방 선택을 확인했습니다.

Android 모서리 반경 모듈은 API 31 이상에서 네 모서리 값을 읽습니다. 에뮬레이터의 시스템 반경은 모두 0이어서 기본 32dp로 표시됩니다. 실제 Samsung 기종별 곡률은 미검증입니다. iOS·macOS·Windows의 이번 전환 실행 검증과 모바일 웹의 실제 터치 검증은 별도입니다.

왼쪽 페이지 후속 변경에서는 Promlive 이름·검색바·채팅방 목록·하단 사용자 이름과 설정 버튼만 남겼습니다. Android S25 에뮬레이터에서 검색으로 목록을 좁히고 해당 채팅방을 여는 동작을 확인했습니다. 목록의 마지막 메시지가 채팅방별로 분리되고 빈 응답보다 마지막 실제 문장을 사용하는 것을 SQLite 테스트로 확인했습니다. 변경 후 Release 빌드와 `npm run verify`가 통과했습니다. 설정은 연결 전 버튼이며 사용자 이름은 임시 `사용자`입니다.

채팅 시작 화면과 왼쪽 내역으로 단순화한 현재 버전은 Android API 36의 새 `Promlive_S25_API36` 에뮬레이터에서 확인했습니다. 1080 × 2340 / 420dpi 기준 입력바 높이는 기본 194px, 한 줄 299px, 두 줄 364px, 최대 463px입니다. 키보드 열기·닫기, 확대 편집 후 축소, 로컬 메시지 저장, 새 채팅·내역 재열기, 작성 중 입력의 프로세스 재시작 복구를 확인했습니다.

Android 16의 키보드 겹침과 닫은 뒤 여백이 남는 현상을 수정했습니다. Metro의 기존 전체 `build` 디렉터리 제외 규칙이 의존성 `pretty-format/build`도 제외하는 문제를 앱 산출물 경로만 제외하도록 수정하여 Debug/Fast Refresh 실행을 복구했습니다.

변경 후 `assembleDebug`, `assembleRelease` 모두 성공했습니다. 실시간 공동 확인을 위해 에뮬레이터에는 Debug 앱을 설치한 상태로 두었습니다. 앱 크래시 로그는 없었습니다. [시작 화면](screenshots/android-s25-chat.png)과 [채팅 내역](screenshots/android-s25-history.png)을 저장했습니다.

웹 412 × 853에서 한글 입력, 최대 높이, 전송 후 초기 높이 복귀, 내역 검색·재열기를 확인했습니다. Samsung One UI·실기기 폰트·키보드의 픽셀 일치는 검증하지 않았습니다. [S25 화면 기록](S25_UI.md)에 치수와 재실행 방법이 있습니다.

아래 플랫폼별 표의 macOS·iOS·Windows 및 카드 기능은 **이전 UI**의 검증입니다. 새 채팅 UI의 모든 플랫폼 실행을 의미하지 않습니다.

## 설정 입력 팝업 확인 (2026-09-22)

- API 키·주소·모델 설정과 일반 설정의 텍스트 입력을 버튼형 미리보기로 전환. 일반 텍스트는 최대 3줄, API 키는 마스킹하며 눌렀을 때만 편집기를 생성합니다. 목록 검색은 결과와 함께 입력하도록 유지합니다.
- API 키는 편집 팝업 안에서 바로 표시하고, 팝업의 제목·보기/숨기기 버튼 대신 공통 상단 규격의 체크 버튼으로 입력을 마칩니다. 팝업 밖 미리보기에서는 계속 마스킹합니다.
- 공통 채팅 입력창의 90% 팝업 크기와 설정 팝업의 드래그·닫기 동작을 사용합니다. 긴 글은 내부 스크롤, 짧은 글 아래의 빈 공간은 팝업 드래그가 처리합니다.
- S25 / Android API 36 Debug 앱: 임시 키 입력 → 닫기 → 앱 강제 종료·재실행 → 값 복원 확인 후 테스트 키 제거. 원래 빈 값으로 복원했고 실제 API 요청은 보내지 않았습니다.
- 같은 에뮬레이터에서 키보드 표시·숨김 중 팝업 위치 유지, 키보드를 숨긴 뒤 편집 영역 복원, 빈 공간 드래그 닫기, 긴 글 내부 스크롤, X 직후 즉시 뒤로가기 스와이프를 확인했습니다. 테스트 프롬프트는 남기지 않았습니다.
- 웹에서도 버튼 클릭 시 편집기 포커스, 배경 접근성 숨김, Escape 닫기를 확인했습니다.

- 공통 상단 버튼 영역과 채팅 입력바 뒤에 테마별 점진적 흐림을 적용했습니다. 버튼과 글자는 선명하게 유지하고, 본문 방향으로 흐림이 사라집니다. 입력바 확대 시 하단 흐림도 함께 사라집니다.
