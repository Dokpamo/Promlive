# 첫 개인 확장: 대화 요약

범용 SDK를 먼저 확정하지 않고 생성 → 검토 → 적용 → 실행 → 저장 → 비활성화 → 복원을 검증하는 첫 사례입니다. 지원 범위는 대화 요약 한 종류입니다.

## 사용 흐름

1. 설정 → AI에서 xAI API 키와 대화 모델을 설정합니다. 이 경로의 실제 생성만 연결했으며 다른 제공자와 OAuth는 기존 설정 UI 범위입니다.
2. 설정 → 플러그인에서 원하는 버튼 이름·요약 방식 등을 적고 AI로 만듭니다.
3. 새 버전의 이름·버튼·요약 지시·읽을 메시지 수를 확인합니다. 예제 대화 미리보기는 허구의 나린·도윤 대화만 모델에 보내며 실제 대화/저장 공간을 사용하지 않습니다.
4. 권한 허용하고 적용을 누르면 상단 요약 버튼이 나타납니다.
5. 버튼을 누른 방의 최근 메시지로 요약하고 방별 결과를 보관합니다. 결과 화면은 최근 10개 요약과 각 버전·메시지 수를 보여 줍니다.
6. 사용 스위치로 비활성화하거나 버전 기록을 선택해 이전 버전을 복원합니다. 비활성화·버전 전환은 실행 중 작업을 취소합니다.

## 첫 계약의 범위

AI는 [summaryProgram](../src/extensions/summaryProgram.ts)의 엄격한 JSON Schema를 따르는 문서를 작성합니다. `readConversation → generate → saveSummary` 세 동작만 있습니다. 실행 호스트는 이 순서를 해석하고, 기존 `CreatorHost`로 모델 요청을 수행합니다. 사용자의 JavaScript를 평가하지 않으며 버튼의 스타일·배치와 결과 시트는 앱이 렌더링합니다.

권한은 현재 방 메시지 읽기, 사용자 선택 모델 호출, 자체 결과 저장의 세 가지입니다. 생성 문서의 선언만으로 권한이 생기지 않고, 검토 후 적용할 때 호스트가 승인 목록을 저장합니다. 실행과 결과 저장에서 승인·활성 버전·실행 리비전을 다시 확인합니다. 확장은 API 키, 임의 주소, 원본 메시지 수정/삭제, 다른 방 지정, 네이티브 API에 접근할 수 없습니다.

최대 최근 200개 중 지정한 메시지 수를 읽으며 모델의 문자 예산에 맞춰 최근 내용부터 포함합니다. 제외된 예전 내용까지 요약했다고 표시하지 않고 실제 사용한 메시지 수를 결과에 남깁니다. 마지막 메시지 하나가 예산보다 크면 임의로 잘라 요약하지 않고 오류를 표시합니다. 실제 토큰 계산은 후속 범위입니다.

## 저장과 복원

- `personal_extension_versions`: 불변 프로그램 문서. 검토 중인 버전과 활성 버전 포인터는 별개입니다.
- `personal_extensions`: 승인한 권한, 사용 여부, 변경 리비전, 실행 권한 리비전. 새 초안 저장은 실행 권한 리비전을 바꾸지 않습니다.
- `personal_extension_results`: 대화 ID와 프로그램 버전에 묶인 결과. 대화 삭제 시 해당 결과만 삭제합니다.

실행은 클릭 시 받은 대화 ID를 끝까지 사용합니다. 나중에 다른 방을 열어도 결과를 그 방으로 보내지 않습니다. 비활성화 후 늦게 도착한 결과는 저장 트랜잭션에서 거부합니다. 코드 버전을 복원해도 이미 저장한 요약은 보존합니다. 호환되지 않는 프로그램은 실행하지 않고 이전 정상 버전을 복원할 수 있습니다.

## 다음 사례에서 결정할 것

두 번째·세 번째 기능에서 실제 공통점이 확인될 때만 추가 명령·화면·권한 계약을 넓힙니다. 레이아웃 교체, 전체 메시지 렌더러, 임의 코드 설치, 확장 마켓, 새 네이티브 기능은 이번 범위에 포함하지 않습니다. 기존 코드 카드의 Creator SDK v1은 별도 기능으로 유지합니다.
