# 채팅 입력바 — 기본 두 단 구조

2026-10-01. 기존 새 UI 입력바와 전체 화면 작성창을 제거하고 `src/ui/chat-input/`에 다시 작성했다.

## 사용자 기준

- 빈 상태부터 위에 작성 영역, 아래에 플러스·전송 버튼을 둔다.
- 초점이나 키보드 유무로 한 줄형/두 단형을 전환하지 않는다.
- 앞의 Threads 사진 3장은 좌우 간격과 회색 배경 참고, 뒤의 사진 4장은 텍스트 위/버튼 아래 배치 참고다.
- 플러스는 입력바 안에 통합하고 전송은 정원으로 표시한다.
- 기기 곡률에 따라 입력바를 변형하지 않는다. 입력바 모서리는 같은 값이며 OS 안전 영역은 피한다.

## 치수와 색

618px 사진 폭을 앱의 412dp에 환산한다. 앞의 사진에서 플러스와 입력바를 합친 전체 외곽은 좌우 약 14px 간격이며, 넓은 입력 배경의 주된 색은 `#F5F5F5`였다. 버튼을 하나의 배경에 합치므로 원본 입력칸만의 왼쪽 103px 간격은 사용하지 않는다.

412dp, 기본 글꼴 크기 기준:

| 항목 | 값 |
|---|---|
| 좌우 간격 | 9.33dp |
| 하단 간격 | OS safe bottom + 9.33dp |
| 키보드 위 간격 | 9.33dp |
| 모서리 반지름 | 모든 상태에서 25.33dp |
| 빈 상태/한 줄 기본 높이 | 106dp |
| 두 줄 높이 | 약 127~128dp — 실제 글꼴 측정값에 따라 반올림 |
| 텍스트 | 17sp, 줄 높이 24.67dp |
| 텍스트 좌우/위 여백 | 18dp / 14dp |
| 텍스트와 버튼 행 간격 | 12dp |
| 버튼 행 아래 여백 | 8dp |
| 전송 원 / 터치 영역 | 40dp / 최소 44dp |

`inputSurface` 역할은 기존 공통 neutral 팔레트의 nearWhite를 재사용한다. 다크 팔레트에서는 기존 darkSurface를 사용한다. 앱 전체 테마 연결 범위는 변경하지 않았다.

## 구조와 동작

- `ChatInput.tsx`: 입력 배경, 하나의 텍스트 입력, 하단 액션 행, 미전송 이미지 표시.
- `geometry.ts`: 텍스트·이미지로 필요한 높이를 계산한다. 초점이나 빈 글 여부에 따른 별도 배치 분기는 없다.
- `InputField.tsx`: 하나의 네이티브 TextInput이 초점·선택·긴 글 스크롤을 담당한다. 이전 입력칸에서 다른 입력칸으로 초점을 전달하는 기능은 없다.
- `InputField.web.tsx`: 같은 구조의 textarea. 측정용 입력과 실제 편집 입력은 분리돼 있으며 측정용 입력은 접근성·탭 순서에서 제외한다.
- `KeyboardDock.tsx`, `.android.tsx`: iOS 키보드 프레임과 Android OS IME 브리지에 연결한다. 네이티브 뷰 등록은 `NativeKeyboardSurface.ts`에 분리한다.

글이 두 줄 이상으로 늘면 버튼의 하단 위치를 고정한 채 텍스트 영역과 바의 위쪽이 늘어난다. 최대 7줄 이후에는 TextInput 자체가 스크롤한다. 별도 확대 버튼, 전체 화면 작성창, 복귀용 커서·스크롤 상태 머신은 없다. 줄 수에 따른 높이 변화만 180ms로 연결하고 OS 동작 줄이기 설정을 존중한다.

전송 버튼은 항상 있다. 공백뿐이고 첨부도 없으면 비활성이며, 글 또는 첨부가 있으면 즉시 활성화한다. 플러스는 기존 카드 갤러리 첨부에 연결한다. 전송과 초안 저장은 새 UI의 ScreenMemory를 사용한다.

## 메시지 전송과 본문 읽기

2026-10-02. 승인한 전송 시안 1번(실제 화면 참고)을 적용했다. 전송은 즉시 로컬 저장하며, 새 말풍선은 오른쪽 정렬을 유지한 채 입력 영역에서 올라온다. 620ms 동안 가로 최대 5%, 세로 최대 2% 눌렸다가 작은 반동과 함께 복원된다. 기존 대화의 이동과 여러 줄 입력바의 축소도 같은 진행 곡선을 사용한다.

새 행과 최종 스크롤 범위를 측정하는 동안 보이는 대화 행을 유지한다. 실제 스크롤 위치가 준비되면 기존 행의 위치를 보정한 상태에서 애니메이션을 시작하므로 첫 프레임이 아래로 튀지 않는다. 이동용 말풍선은 최종 행과 같은 크기·줄바꿈·모서리·팔레트를 사용하며 접근성 읽기에서는 제외한다. 화면 복원 시 재생하지 않으며, 연속 전송·스크롤·화면 높이 변경·동작 줄이기에서는 이전 효과를 안전하게 끝낸다. 화면보다 긴 메시지는 바로 일반 스크롤 행으로 표시한다.

본문을 짧게 누르면 상단바와 입력바를 숨기며 다시 누르면 복원한다. 스크롤과 긴 누르기는 토글하지 않는다. 숨김 상태에서도 대화 맨 위에 가까워지면 상단바가 스크롤에 맞춰 드러나고, 다시 아래로 이동하면 숨겨진다. 드러난 뒤로가기·메뉴 버튼은 바로 사용할 수 있다. 상단바는 본문 위에 겹쳐 표시하며, 숨김/복원 시 본문 높이·스크롤 위치·메시지 좌표를 바꾸지 않는다. 첫 메시지 위의 여백은 항상 일정하다. 화면보다 짧은 대화는 두 바를 모두 유지한다.

숨김 상태의 입력바는 마지막 메시지 다음에 놓인 것처럼 스크롤과 같은 거리로 움직인다. 맨 끝에서 켜지는 별도 페이드나 시간 애니메이션 없이 아래에서 보이기 시작해 원래 위치에 도착하고, 거꾸로 스크롤하면 같은 경로로 내려간다. 모바일에서는 스크롤 오프셋을 네이티브 Animated 값에 직접 연결한다. 입력 중이나 전송 중에는 원래 위치에 고정하며, 숨겨도 입력 노드와 초안을 유지한다.

`KeyboardViewport`는 본문의 현재 레이아웃 높이와 네이티브 입력바의 키보드 이동량을 합쳐 보이는 높이를 제공한다. 키보드가 움직일 때 이전 프레임의 ScrollView 높이로 끝 위치를 계산하지 않는다. 실제 키보드 이동은 기존 iOS/Android 네이티브 뷰가 계속 담당한다.

모바일의 화면 높이 변경에서는 네이티브 스크롤 보정을 사용한다. JS에서 중간 레이아웃마다 다시 끝으로 이동시키면 키보드 이동 중 끝 위치가 어긋날 수 있으므로, 그 보정은 웹에서만 실행한다.

입력의 터치는 페이지 뒤로가기보다 우선한다. 기본 입력 하나가 네이티브 선택과 스크롤을 처리하므로 확대/축소에 따른 초점 반환이나 선택 복원이 필요하지 않다. 대화방을 나가거나 첨부를 열 때 Android의 대기 중인 키보드 요청도 함께 정리한다.

## 제거 범위

기존 `src/ui/ChatComposer.tsx`, `ExpandedChatComposer.tsx`, `ComposerTextInput*`, `ComposerEditing*`, `ComposerCircle`, `ComposerKeyboard*`, `chatComposerGeometry`, 확장/복원 관련 훅을 제거했다. `ChatRoom`의 전체 화면 작성 상태와 숨겨진 배경 제어도 제거했다. 이전 기능 UI(`src/features/`)는 기존처럼 앱 진입점에서 분리되어 있으며 새 입력바가 참조하지 않는다.

## 검증

- 빈 상태/초점/초점 해제에서 같은 기본 배치, 항상 있는 전송 버튼과 비활성 처리.

- 첨부 추가/제거 시 기존 초안 유지, 이미지 단독 전송 허용.

- 의존성 검사: 새 앱이 제거한 입력바나 이전 기능 UI를 다시 연결하지 않는다.

자동 검사: 입력바·기하·의존성 9개, UI 통합·카드 저장 26개 통과. TypeScript와 웹 빌드 통과.

2026-10-02 전송·본문 읽기 변경 검증: 관련 자동 검사 52개, TypeScript와 웹 빌드를 통과했다. Android에서 키보드를 열고 여러 줄 전송, 키보드를 닫고 한 줄 전송을 녹화해 이동·착지와 기존 대화 위치를 확인했다. 본문 탭으로 숨김/복원, 끝에서 입력바 유지, 숨김 상태에서 끝까지 스크롤하면 입력바 복귀, 키보드 닫힘과 상단바 접힘이 겹치는 경우를 확인했다. 이 변경의 iOS 실행 검증은 하지 않았다.

후속 조정에서는 상단바를 겹쳐 표시하고 입력바를 스크롤에 직접 연결했다. Android UI 좌표 비교에서 상단바 숨김 전후 메시지 10개, 복원 전후 메시지 12개의 위치가 모두 같았다. 입력바가 일부 보이는 구간에서는 본문과 입력바가 각각 237px 움직여 같은 간격을 유지했다. 일부 드러난 입력칸을 눌러도 기존 초안을 유지한 채 키보드 위에 고정됐다. 관련 자동 검사 41개, TypeScript와 웹 빌드를 통과했다.

상단바의 맨 위 자동 표시도 Android에서 확인했다. 숨김 상태를 유지한 채 맨 위에서 상단바와 메뉴 버튼이 다시 나타나고, 아래로 이동하면 사라진다. 일부 드러난 상단바를 본문 탭으로 복원해도 메시지 11개와 본문 높이는 바뀌지 않았다. 스크롤 중 별도 시간 애니메이션을 만들지 않는 검사, 짧은 대화와 양방향 오버스크롤을 포함한 관련 자동 검사 16개, TypeScript와 웹 빌드를 통과했다. 이 후속 변경의 iOS 실행 검증은 하지 않았다.

### Android 실행 확인

`emulator-5564`, 1080×2340px / 배율 2.625에서 새 빌드를 설치해 확인했다.

- 좌우 간격은 각각 24px이며 키보드 위 간격도 24px이다. 기본 높이는 278px(약 106dp), 두 줄은 336px(128dp)이다.
- 키보드가 열린 상태에서 입력바 하단은 y=1433px로 유지되며, 줄이 늘면 상단만 위로 이동한다. 7줄 이후의 8·9번째 줄은 외곽 높이를 늘리지 않는다.
- 긴 글을 입력 영역 안에서 스크롤하고 가로로 드래그해도 대화방 뒤로가기가 실행되지 않는다.
- 빈 글의 전송 비활성, 텍스트 입력 후 활성, 첨부 추가·제거, 키보드 닫기, 대화방 나가기·다시 들어오기를 확인했다. 검증용 텍스트는 제거하고 원래 초안을 복원했다.
- 처음 연결 시 누락돼 있던 Android 네이티브 키보드 이동 비율을 1로 지정했다. 키보드가 입력바를 가리는 문제는 수정 후 다시 확인했다.
