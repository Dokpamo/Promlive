# 새 UI 공통 색상

2026-09-30. `src/ui/tokens.ts`의 `colorPalettes`에서 밝음·어두움의 색을 역할별로 관리한다. 서재·채팅·생성·설정·카드 편집·상하단 바가 같은 팔레트를 사용하며, 웹 바탕과 포커스 표시도 이 값을 따른다.

## 공통 역할

| 역할 | 밝음 | 어두움 | 사용하는 곳 |
|---|---|---|---|
| `background` | `#FFFFFF` | `#101010` | 화면, 상하단 바, 목록, 알약 줄 |
| `surface` | `#F2F2F2` | `#1E1E1E` | 검색창, 표지·원형 이미지의 빈 자리 |
| `foreground` | `#101010` | `#F5F5F5` | 제목, 본문, 아이콘 |
| `secondaryForeground` | `#777777` | `#777777` | 제작자, 메시지 미리보기, 시각, 안내, 입력 힌트 |
| `controlForeground` | `#5B5B5B` | `#F5F5F5` | 선택하지 않은 알약의 글자 |
| `separator` | `#EDEDED` | `#1E1E1E` | 탭바 구분선, 입력칸 아래 선 |
| `border` | `#D8DCDE` | `#3A3A3A` | 윤곽선 |
| `selectedBackground` | `#191919` | `#F5F5F5` | 선택한 알약 |
| `selectedForeground` | `#FFFFFF` | `#101010` | 선택한 알약의 글자 |
| `error` | `#B32323` | `#FF8A8A` | 입력 오류 |

다크 바탕·검색 면·글자는 `photo_6188283593155613331_y.jpg`에서 확인한 색을 기준으로 한다. **선택한 알약은 사용자의 별도 지시에 따라 흰 계열 배경·검은 글씨를 유지한다.** 사진 속 선택 배경 `#1E1E1E`를 그대로 적용하지 않는다. 선택하지 않은 다크 알약은 화면과 같은 바탕에 윤곽선으로 구분한다.

프로필 그림의 바탕·윤곽·실루엣도 같은 파일에서 관리한다. 사진처럼 밝은 프로필 그림을 유지하기 위해 두 모드가 이 세 색을 공유한다. 카드의 미리보기 이미지 자체는 팔레트 색으로 바꾸지 않는다.

## 적용 범위

- 각 컴포넌트는 `colors`의 역할을 사용하고 별도의 회색 값을 정의하지 않는다. `filterChipColors`도 공통 팔레트에서 파생한다.
- 라이트 구현 재점검: 실행 경로인 `src/ui`와 `web/main.tsx`·`web/styles.css`에서 제목·아이콘, 검색 면·이미지 빈 자리, 제작자·미리보기·시각·힌트, 알약 선택/비선택 색의 공통 참조를 확인했다. 별도 디자인 검토용 `web/previews`는 앱 진입점에서 불러오지 않으므로 이 팔레트 점검 범위에 포함하지 않는다.
- 현재 `uiAppearance`는 `light`다. 다크 팔레트는 준비해 두며, 사용자 설정이나 시스템 테마의 자동 전환은 아직 연결하지 않는다.
- 알약 치수·글자 크기·상하단 바 위치·스크롤과 편집 동작은 바꾸지 않는다. 알약 치수는 [UI_FILTERS.md](UI_FILTERS.md)를 따른다.

## 확인

- TypeScript 검사, 새 UI 관련 테스트 27개, 웹 빌드를 통과했다.
- Android에서 밝음·어두움 렌더링, 선택 알약 변경, 검색 열기·닫기, 서재·채팅·생성 전환을 확인했다. 다크 선택 면 `#F5F5F5`, 비선택 면 `#101010`, 테두리 `#3A3A3A`, 검색 면 `#1E1E1E`를 캡처에서 확인했다.
- 두 모드의 ‘전체’ 면은 174 × 113px, 글자는 72 × 39px로 동일했다. 상단 `[0,63]–[1080,231]`·하단 `[0,2132]–[1080,2340]` 위치와 밝은 검색 면 `#F2F2F2`도 확인했다.
- 검사용 다크 설정을 제거하고 `uiAppearance = 'light'` 및 실제 밝은 서재 화면으로 복귀했다.
