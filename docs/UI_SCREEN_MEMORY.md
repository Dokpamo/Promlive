# 화면 기억과 백그라운드 갱신

2026-09-30 사용자 합의: **마지막으로 보던 화면을 먼저 보여주고, 최신 내용을 뒤에서 확인해 달라진 부분만 반영한다.** 새 화면과 데이터 연결에도 이 원칙을 공통 적용한다.

## 화면을 여는 순서

1. 첫 React 렌더 전에 기기 안의 마지막 스냅샷을 읽는다. 네트워크를 기다리지 않는다.
2. 저장된 탭·본문·검색·분류·스크롤·상단바 상태를 복원한다. 실행 중에는 `TabPages`가 네 탭과 서재·생성의 필터별 페이지를 유지해 재마운트를 피한다.
3. 첫 렌더 후, 앱이 다시 활성화될 때, 웹의 저장소가 변경될 때 최신 데이터를 확인한다.
4. ID와 내용이 같은 레코드는 기존 객체·화면을 유지한다. 바뀐 내용만 React에 반영하고 목록을 비우거나 전체 로딩 화면으로 교체하지 않는다.
5. 갱신 실패 시 현재 내용을 유지한다. 저장에 실패한 편집 내용이 남아 있으면 갱신을 보류하고, 응답을 기다리는 동안 사용자가 편집했다면 그 응답은 적용하지 않는다.

여기서 저장하는 것은 다시 상호작용할 수 있는 데이터와 UI 상태다. 키보드와 임시 터치 효과는 복원하지 않는다. 저장된 검색창이 열려 있어도 앱 재실행만으로 키보드를 자동 호출하지 않는다.

네이티브에서 상세·편집이 다른 화면을 가릴 때도 아래 화면의 레이아웃 크기는 유지한다. 숨긴 목록의 높이를 0으로 만들면 네이티브의 가시 항목 유지가 스크롤을 바꿀 수 있으므로, 탭 전환과 같은 레이어 방식으로 터치·접근성과 표시만 차단한다.

## 저장 범위

| 내용 | 저장/복원 |
|---|---|
| 마지막 탭 | 서재·채팅·생성·설정 |
| 검색 | 각 탭의 열림 상태와 검색어 |
| 분류 | 서재와 생성의 선택 필터 |
| 목록 | 필터별 스크롤 거리·상단바 숨김 거리·상단 높이·스크롤 범위 |
| 설정·편집 | 본문 스크롤 위치 |
| 편집 | 열린 카드 ID, 초안의 입력 내용, 마지막 완료본 |
| 카드 상세 | 열린 완료본 카드 ID, 본문 스크롤 위치, 편집 후 돌아올 상세 |
| 이미지 감상 | 대표 이미지 열림 상태, 갤러리에서 선택한 사진 번호 |
| 채팅방 | 열린 대화 ID, 메시지, 입력 중 글과 첨부 이미지, 대화별 스크롤 위치 |
| 카드/채팅 표시 데이터 | 안정된 ID, 제목·메시지·제작자·수정 시각 등 |
| 이미지 | 번들 이미지의 타일 번호와 갤러리 ID·제목. 비트맵을 JSON에 중복 저장하지 않는다. |

초안과 완료본을 분리하는 기존 동작은 같다. 새 초안은 완료 전까지 서재에 나타나지 않는다. 외부 카드 편집 중에는 이전 완료본이 서재에 유지된다. 재실행 시 시각을 새로 만들어 데이터가 갱신된 것처럼 보이지 않도록 기존 타임스탬프도 저장한다.

## 코드 역할

- `screenState.ts`: 버전 1 문서, 검증, 초기 데이터, 변경된 레코드만 교체하는 병합.
- `ScreenMemory.ts`: 캐시를 먼저 읽는 저장소. 화면 구독, 입력 저장, 순차 쓰기, 백그라운드 `refresh(loader?)`, 실패 보존을 담당한다.
- `screenPersistence.ts` / `screenStorage.*`: 동기 초기 읽기와 저장·재확인 포트.
- `useScreenMemory.ts`: 첫 화면 후 갱신, 앱 복귀·웹 저장소 변경 시 재확인, 백그라운드/페이지 종료 시 저장.
- `useScrollHeader.ts`: 저장된 본문 위치와 상단 숨김 거리를 같은 Animated 그래프로 복원. 검색 변경 시 맨 위부터 표시하고, 분류 이동 시에는 해당 필터의 마지막 위치를 복원한다. 본문 가로 제스처로 알약을 넘길 때는 현재 상단 숨김 거리를 목적지에 전달해 상단이 튀지 않게 한다. 짧은 목록은 이 상태를 다시 펼칠 최소 스크롤 범위도 복원한다. 이전 탭별 스냅샷은 당시 선택했던 필터의 위치로만 옮긴다.
- `usePlainScrollMemory.ts`: 설정·카드 상세·편집·대화별 ScrollView 복원.

2026-10-01: 기존 버전 1 문서에서 태그·갤러리·가이드와 로컬 대화 데이터가 없으면 새 필드만 보충한다. 도서관의 예전 예시 소개·인트로만 더 풍부한 예시로 바꾸며 사용자 편집은 유지한다. 갤러리 번호와 대화 ID는 실제 데이터에 존재하는 값만 복원한다. 열린 채팅방과 미전송 글·이미지를 첫 렌더에 복원해도 키보드는 자동으로 열지 않는다.

스크롤 기록은 React 구독자에게 매 프레임 통지하지 않는다. 160ms 단위로 저장을 모으고 앱이 배경으로 갈 때 남은 값을 저장한다. 입력·탭 변경은 메모리에 즉시 반영하고 저장 작업을 시작한다. 저장이 진행되는 동안의 추가 변경은 이어서 저장하며 오래된 쓰기가 새 내용을 덮지 않도록 순서를 유지한다.

## 저장 위치와 복구

- 카드·대화 내용과 탭·검색·스크롤 등 화면 상태를 따로 저장한다. 화면 이동만으로 오래된 카드·대화 전체를 다시 저장하지 않는다. 기존의 합쳐진 버전 1 문서도 읽을 수 있다.
- 합쳐진 구형 문서의 화면 상태는 별도 저장에 성공할 때까지 이관 미완료로 취급한다. 그동안 내용을 수정해도 화면 상태를 본문에 함께 남겨 두므로 두 저장 단계 사이의 실패·종료에도 복원할 수 있다. 화면 저장소를 읽지 못하면 복구한 원본 화면만 보존하며 임시 화면으로 덮어쓰지 않는다. 이관 성공 후 다음 내용 저장부터 화면 필드를 제외한다.
- Android/iOS/macOS: `@op-engineering/op-sqlite`의 `promlive-ui-memory.sqlite`. 콘텐츠와 화면 상태는 서로 다른 행이다. 콘텐츠는 원본이 여전히 같은 경우에만 갱신하는 단일 SQL 문으로 비교·저장·정상본 백업을 원자적으로 처리한다. 테이블 생성에 성공한 핸들만 캐시하며 실패한 핸들은 닫고 재시도한다.
- 웹: 콘텐츠는 `localStorage`의 `promlive:screen:local:v1` 및 `:backup`. Web Locks 안에서 원본 비교와 교체를 수행하며 잠금을 지원하지 않는 환경은 쓰기를 차단한다. 별도 `:view` 키로 화면 상태를 저장한다. 열린 창은 각자의 `sessionStorage` 값을 유지하고, 새 브라우저 세션은 `localStorage`의 마지막 화면을 복원한다.
  화면 상태는 `localStorage` 저장 후 `sessionStorage`에 반영한다. 영구 저장 실패를 같은 탭의 재실행에서 저장 성공으로 오인하지 않도록 한다.
- Windows: LocalAppData/Promlive의 JSON을 임시 파일에서 교체한다. 프로세스 간 named mutex 안에서 원본 비교·정상본 백업을 수행한다. 화면 상태는 `screen-view.json`에 따로 기록한다. 읽기 오류를 빈 파일로 취급하지 않는다. 네이티브 모듈 변경이므로 Windows 앱 재빌드가 필요하다.
- 다른 창이 내용을 먼저 저장했으면 덮어쓰지 않고 충돌을 알린다. 이미 저장된 다른 창의 내용과 이 창의 메모리에 남은 미저장 편집을 보존한다. 충돌한 편집을 자동 병합하거나 저장 완료로 표시하지 않는다.
- 저장된 내용의 **없음 / 손상 / 미지원 버전 / 읽기 실패**를 구분한다. 본문과 백업이 모두 없을 때만 샘플로 시작한다. 손상된 본문은 정상 백업에서 복원하되, 손상본을 정상 백업 위에 기록하지 않는다. 미지원 버전은 이전 백업으로 되돌려 쓰지 않는다.
- 기존 내용을 읽지 못하면 원본 바이트를 보존하고 내용 편집·자동 저장을 중단한다. 재시도로 원본이나 정상 백업을 읽은 뒤에만 편집을 허용한다. 재시도에서 본문·백업 모두 없음이 확인되면 새 작업공간을 초기화한다.
- 쓰기 실패 시 화면과 미저장 편집을 유지한다. `flush()`는 저장 종료 직전 마이크로태스크에서 들어온 변경까지 재확인한다. 저장 단계가 실패해도 정상 본문이나 정상 백업 중 하나는 남도록 한다.
- 기존 `storyloom.sqlite`, 구형 UI·Workspace·AI·프로필 저장소는 연결하거나 지우지 않는다.

앱이 강제 종료되는 순간까지 완료되지 않은 디스크 쓰기는 복원이 보장되지 않는다. 정상적인 화면 이동·백그라운드 전환 시 저장하고, 쓰기가 완료된 상태의 강제 종료·재실행을 검증한다. 저장된 초안을 일회성 캐시로 취급해 TTL 만료만으로 지우면 안 된다.

## 새 화면/실제 데이터 연결 시 규칙

- 새 화면의 복원 상태는 이 공통 저장소에 추가한다. 화면별로 로딩 화면·별도 타이머·복원 후 강제 초기화를 만들지 않는다.
- 실제 데이터 서비스는 `ScreenMemory.refresh(() => source.load())`에 연결한다. 실패하면 기존 화면을 유지한다. 안정된 ID를 사용하고 바뀌지 않은 항목을 재생성하지 않는다.
- 현재 기본 갱신 소스는 **새 UI의 로컬 저장 문서**다. 네트워크 서버나 실제 AI 채팅은 아직 없다. 동기화가 연결된 것처럼 더미 데이터를 주기적으로 바꾸지 않는다.
- 태그 입력의 쉼표·공백 등 원시 문자열은 해당 카드와 정규화한 태그 값에 연결한다. 외부 갱신으로 태그 값이 달라지면 열린 입력창에도 즉시 반영하고, 로컬 타이핑이나 태그가 동일한 갱신에서는 문자열과 커서를 유지한다. 충돌로 거절된 갱신은 미저장 입력을 바꾸지 않는다.
- 서버 연결 시에는 출처별 버전/삭제/충돌 정책을 명시하고, 미전송 초안과 서버 데이터를 구분한다. 로그인 기능을 붙일 때는 저장 키를 계정별로 나누고 세션 변경 시 이전 계정의 화면을 노출하지 않는다.
- 외부 이미지를 도입하면 데이터 캐시와 별도로 로컬 파일/디스크 캐시 및 갱신 정책을 연결한다. 현재 번들 이미지는 오프라인에서도 이용 가능하다.
- 더 큰 목록을 연결할 때는 화면에 필요한 페이지와 사용자가 작성한 원본을 구분해 저장한다. 현재 구현은 작은 로컬 미리보기 작업공간 전체를 저장한다.

## 검증

- `ui-screen-memory`: 재실행 직전 상태의 동기 복원, 구형 화면 이관·쓰기 중단·읽기 오류 후 복구, 변경 레코드만 갱신, 실패·지연 응답·순차 저장·복구·스크롤 저장.
- `screen-storage-web`: 여러 작성자의 충돌, 백업 복구 중 용량 부족, 각 저장 단계 실패, 창별 화면과 새 세션 복원을 검증한다.
- `screen-storage-native`: 실제 SQLite 엔진으로 조건부 갱신·백업 보존·초기화 실패 후 재시도를 검증한다. OP-SQLite 브리지의 기기 오류 주입 검증을 대신하지는 않는다.
- `ui-shell`: 복원된 편집 화면, 검색·분류·초안 유지, 갱신 중 화면과 변경되지 않은 행의 DOM 유지, 기존 편집·완료 흐름.
- `ui-card-editor`: 실제 React/ReactDOM(jsdom)과 웹 저장 어댑터로 모바일·데스크톱 레이아웃의 외부 태그 갱신 후 편집, 원시 입력·커서 유지, 충돌 시 양쪽 편집 보존을 검증한다.
- `ui-scroll-header-animation`: 저장된 중간 상단 위치를 복원한 뒤 다음 드래그와 연결.
- Android 16 에뮬레이터에서 프로세스 강제 종료/재실행 후 서재 카드 좌표, 열린 편집 화면, 생성 필터, 채팅 탭·검색어와 키보드 미호출을 확인했다.
- Windows 네이티브 어댑터와 iOS/macOS 실행은 이 macOS/Android 검증 환경에서 별도 빌드·실행하지 않았다.
