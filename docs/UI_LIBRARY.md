## 참고 이미지와 배치

기준: `photo_6188107052819878684_y.jpg` (618 × 1280px).

- 열 하나의 이미지 폭은 약 204px, 높이는 약 273px다. 폭/높이 약 0.747이므로 **3:4**에 해당한다. JPEG 경계 오차를 고려한 측정이며 물리 기기의 dp는 아니다.
- 세 열이 화면 양끝까지 이어진다. 좌우 바깥 여백·둥근 모서리·카드 테두리·그림자를 두지 않는다.
- 가로·세로 간격은 참고 폭에서 3px. 412dp 화면에서는 2dp로 적용한다.
- 표지의 폭은 `(사용 가능한 본문 너비 - 간격 × 2) / 3`, 높이는 `폭 × 4 / 3`이다. 반올림은 네이티브 레이아웃에 맡긴다. 글자 영역을 포함한 카드 전체 높이는 3:4로 제한하지 않는다.
- 사용자가 선택한 이미지 아래 배치를 적용한다. 흰 바탕에 제목 최대 두 줄(14sp, 줄 높이 19dp, 굵기 600), 제작자는 한 줄(12sp, 줄 높이 17dp, 공통 보조 글자색 `#777777`)만 표시한다. 제목은 두 번째 줄, 제작자는 첫 번째 줄 끝에서 넘치는 내용을 `…`으로 처리한다. 색상 역할은 [UI_COLORS.md](UI_COLORS.md)를 따른다.
- 글자 영역은 좌우 7dp, 위 7dp, 아래 12dp를 띄우고 제목과 제작자 사이는 3dp다. 짧은 제목에 빈 두 번째 줄을 강제로 확보하지 않는다. 같은 행의 다음 표지들은 행에서 가장 높은 카드 뒤에 정렬된다.
- 참고 화면의 조회수는 복제하지 않는다. 제목·캐릭터·제작자는 접근성 이름과 검색 정보에도 포함한다.
- 상단 제목과 하단 탭바의 기존 보정 치수는 [UI_NAVIGATION.md](UI_NAVIGATION.md)를 유지한다. 상단 영역은 카드 스크롤의 정상 이동 거리를 따라가며, 탄성 효과가 적용되는 목록과는 별도 레이어다. 하단 탭바와 OS 안전 영역은 고정된다.

## 분류와 검색

- 상단바 바로 아래에 **전체 · 요즘 한 거 · 방치 중** 분류를 가로로 둔다. 제목과 왼쪽 시작선을 맞추고, 폭이 부족하면 가로로 스크롤한다.
- 생성과 `FilterChips`를 공유한다. 카카오톡 참고 사진을 618px 폭으로 환산한 알약 면 약 65px 높이, ‘전체’ 약 100px 폭에 맞추고, 화면 폭에 따라 글자·안쪽 여백·간격을 함께 조절한다. 터치 영역은 최소 48dp 높이를 확보한다. [UI_FILTERS.md](UI_FILTERS.md)에 치수와 밝음·어두움 팔레트를 기록한다.
- 밝은 화면에서는 선택한 분류가 `#191919` 바탕·흰 글자, 나머지가 `#F2F2F2` 바탕·`#5B5B5B` 글자다. 412dp 화면의 글자는 16sp, 줄 높이 약 21.3dp, 굵기 700이다.
- 선택하면 해당 분류의 더미 카드만 표시하고 목록을 맨 위부터 보여 준다. 분류 줄은 제목과 함께 스크롤된다. 실제 사용 기록이나 저장소에 연결하지 않고 더미의 `activity` 값으로만 구분한다.
- 상단 오른쪽은 **검색 → 플러스** 순서다. 검색과 플러스는 같은 아이콘 프레임과 터치 영역을 사용한다.
- 검색 필드는 처음에는 숨겨 둔다. 검색 버튼을 누르면 분류 줄 아래에 나타나며 선택한 분류 안에서 미리보기 카드의 제목·캐릭터·제작자를 필터링한다.
- 검색어 지우기, 검색 결과 없음, 검색 닫기를 제공한다. 닫으면 검색어를 비운다.
- 검색 버튼 외 기존 추가·작성 동작은 계속 비활성이다. 카드 선택·상세·파일 가져오기·저장소 연결은 이 단계에 추가하지 않는다.

## 상단 영역의 스크롤

- 상단과 본문은 [UI_SCROLLING.md](UI_SCROLLING.md)의 네이티브 이벤트 경로로 동기화한다. `Animated.FlatList`의 위치를 같은 네이티브 Animated 그래프에서 상단 이동량으로 계산하며, 매 프레임 자바스크립트를 거쳐 상단을 다시 옮기지 않는다.
- `ScrollFrame`에서 제목·검색/추가 버튼·분류·열린 검색 필드를 본문 `FlatList`와 형제인 상단 레이어로 둔다. 실제 상단 UI는 네이티브 스크롤 컨테이너 안에 넣지 않는다. 목록의 첫 부분에는 측정된 상단 높이만큼 빈 공간만 둔다. 제목과 분류의 기본 합산 높이는 120dp이며, 실제 레이아웃으로 높이를 다시 측정한다.
- 아래 내용을 보려고 스크롤하면 상단 영역과 카드가 같은 거리만큼 위로 움직인다. 상단이 전부 사라진 후에도 빈 자리를 남기지 않는다. 상단 영역에서 시작한 세로 드래그도 같은 목록을 움직인다.
- 반대로 스크롤하면 화면 깊이에 관계없이 되돌린 거리만큼 상단이 드러난다. 방향이 바뀌었다는 이유만으로 전체가 즉시 나타나지 않는다.
- 손을 놓고 관성 스크롤이 끝나면 현재 노출량에서 더 가까운 끝으로 마무리한다. 절반보다 적게 드러났으면 숨김, 절반보다 많이 드러났으면 완전 표시다. 일반 구간은 목록과 함께 움직이고, 하단 끝에서 상단 높이 이내인 구간은 **상단바만** 마무리해 목록이 손을 놓은 위치에서 되감기지 않게 한다.
- 끝부분 탄성은 서재·채팅의 내부 목록에만 허용한다. 네이티브 목록의 기본 탄성을 켜고 본문 경계에서 클리핑한다. 상단 제목·버튼·분류·검색과 하단 탭바·OS 안전 영역은 탄성에 의해 이동하거나 늘어나지 않는다. 웹은 목록의 스크롤이 바깥 페이지로 이어지지 않게 한다. 탄성으로 범위를 벗어난 거리는 상단바의 숨김/표시 계산에 넣지 않는다.
- 새 터치·드래그가 시작되면 예약된 마무리를 취소한다. 짧은 검색 결과는 도달할 수 없는 위치로 보내지 않으며, 분류·검색·화면 너비 변경 시 맨 위에서 상단 전체를 표시한다. 시스템의 동작 줄이기 설정에서는 마무리 애니메이션을 생략한다.
- 네이티브와 웹 모두 `ScrollFrame`의 상단 레이어를 같은 거리 계산으로 숨기고 나타낸다. 충분히 스크롤되지 않는 짧은 목록은 상단을 유지한다. 상단에서 시작한 세로 드래그는 목록으로 전달하고, 버튼 탭과 가로 분류 스크롤은 가로채지 않는다. 기존 UI의 스크롤·제스처 코드는 가져오지 않는다.
