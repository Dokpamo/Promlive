# Promlive UI 구조

작성일: 2026-09-29. 상태: 구조 정리 완료, 별도 UI에서 새로 구현 중.

이 문서는 UI를 처음부터 다시 만들 때 남겨 둘 화면, 정보, 기능, 이동 관계를 기록한다. 기존 화면의 모양이나 구현을 복제하는 명세가 아니다. 현재 앱은 [새 UI 진입점](UI_RESET.md)으로 교체했으며, 상단 헤더·하단 탭바와 [새 서재 그리드·검색](UI_LIBRARY.md)을 실행한다. 서재는 미리보기 데이터이고 나머지 본문은 비어 있다. 아래 기능들은 새 화면에 다시 연결할 구조 명세다. 참고 이미지 분석은 [UI_NAVIGATION.md](UI_NAVIGATION.md)에 기록한다.

색상, 글자 크기, 여백, 곡률, 그림자, 아이콘 그림, 목록의 열 수, 버튼 위치, 팝업 형태, 애니메이션 수치는 이 구조 문서에서 정하지 않는다. 별도로 확정한 범위는 해당 디자인 문서를 따르며, 나머지 범위에서는 이전 참고 이미지나 기존 스타일 파일을 새 디자인의 확정 기준으로 취급하지 않는다.

## 1. 앱 전체 구조

```text
Promlive
├─ 서재: 사용할 카드 가져오기·관리·내보내기
│  └─ 카드 → 시작 상황 선택 → 채팅방
├─ 채팅: 실제 대화 찾기·계속하기·관리
│  └─ 전체 / 카드별 대화 → 채팅방
├─ 생성: 새 카드 제작·내 제작물 관리
│  └─ 제작기
│     ├─ AI와 제작 대화
│     ├─ 직접 구성 편집
│     ├─ 대화 시험
│     └─ 포켓 구성·미리보기
└─ 설정
   ├─ 사용자 프로필
   ├─ AI
   ├─ 페르소나
   ├─ 프롬프트
   ├─ 테마·대화 표시
   ├─ 언어
   ├─ 플러그인
   └─ 정보
```

하단의 주요 목적지는 **서재 → 채팅 → 생성 → 설정** 네 개다. 홈·공유 사이트·커뮤니티는 이번 구조에 추가하지 않는다.

채팅방과 제작기는 목록에서 들어가는 작업 화면이다. 화면을 닫으면 진입했던 목록으로 돌아간다. 설정은 설정 탭뿐 아니라 채팅방·제작기에서도 열 수 있고, 닫으면 원래 작업으로 돌아간다.

## 2. 화면이 다루는 대상

| 대상 | 의미와 연결 |
|---|---|
| 카드 | 제목·소개·제작자·태그·표지와 실행 내용을 가진 작품. 서재와 생성은 같은 카드의 용도별 보기다. |
| 제작 초안 | 제작 중인 카드 내용, 제작 대화, 변경 기록. 실제 대화에서 사용하는 카드 버전과 구분한다. |
| 카드 실행 버전 | 대화를 시작할 때 사용하는 완성된 구성. 기존 대화에 새 버전을 반영하는 동작은 별도로 제공한다. |
| 채팅 | 한 카드에 속한 대화. 메시지·입력 중인 문장·현재 장면·적용된 카드 버전을 가진다. 한 카드에 여러 채팅이 가능하다. |
| 분류·폴더 | 카드, 카드별 채팅, 페르소나를 정리하는 용도. 안에 다른 폴더를 둘 수 있다. 정리 위치와 내용 자체는 구분한다. |
| 사용자 프로필 | 앱에서 사용하는 이름과 이미지. |
| 페르소나 | 사용자가 역할로 사용할 이름·설명·이미지의 묶음. 프로필과 구분하며 여러 개를 보관한다. |
| 구성 항목 | 카드 실행에 쓰이는 프롬프트, 포함 조건, 연결 에셋을 가진 항목. |
| 시작 상황 | 시작 프롬프트, 사용자용 인트로, 장소, 활성 항목, 초기 상태값의 묶음. |
| 에셋 | 표지나 구성 항목에 연결되는 이미지·음원·파일. |
| 포켓 | 현재 장소·인물·상태값을 사용자에게 보여 주는 카드의 보조 화면. |

## 3. 서재

목적: 가져온 카드와 완성된 카드를 찾아 사용하고 관리한다. 제작 중인 초안은 생성에서 다룬다.

| 영역 | 필요한 정보·동작 |
|---|---|
| 화면 식별 | 서재 제목, 카드 가져오기 진입점 |
| 검색 | 카드 제목·제작자·소개·태그 검색, 검색어 지우기 |
| 분류 | 전체 보기, 사용자 분류 선택·생성·이름 변경·삭제 |
| 카드 모음 | 표지, 제목, 제작자, 소개 또는 태그, 고정·선택 상태 |
| 카드 동작 | 새 채팅 시작, 편집, 내보내기, 고정·해제, 이름 변경, 분류 이동, 삭제 |
| 다중 선택 | 선택·해제, 전체 선택·해제, 선택 종료, 선택한 카드 관리 |
| 상태 | 로딩, 카드 없음, 검색 결과 없음, 파일 처리 중, 실패·재시도 |

카드를 살펴보거나 선택하는 것만으로 새 대화를 만들지 않는다. 새 채팅을 시작할 때 시작 상황이 여러 개라면 선택 단계로 연결한다.

분류를 지우는 것과 카드 자체를 지우는 것은 별도 동작이다. 카드 삭제 시 관련 대화에 미치는 영향을 확인 단계에서 알 수 있어야 한다.

## 4. 채팅

### 4.1 채팅 목록

목적: 실제 대화를 바로 찾아 이어 간다. 카드 목록을 한 번 더 보여 주는 화면으로 만들지 않는다.

| 영역 | 필요한 정보·동작 |
|---|---|
| 화면 식별 | 채팅 제목, 새 채팅 진입점 |
| 검색 | 대화 제목·카드 이름·최근 메시지 검색 |
| 범위 선택 | 전체 대화, 특정 카드의 대화 |
| 대화 모음 | 연결된 카드 이미지·이름, 대화 제목, 최근 메시지, 날짜, 고정·선택 상태 |
| 대화 동작 | 기존 대화 열기, 고정·해제, 이름 변경, 삭제 |
| 카드별 관리 | 해당 카드의 대화 폴더 탐색·생성·이동 |
| 다중 선택 | 선택·해제, 전체 선택·해제, 선택 종료, 선택한 대화 관리 |
| 상태 | 대화 없음, 검색 결과 없음, 로딩, 실패·재시도 |

전체 보기에서는 카드별 폴더 안에 보관한 대화도 찾을 수 있어야 한다. 서로 다른 카드의 대화를 선택했을 때 가능한 폴더 이동 범위는 명시적으로 정한다.

새 채팅은 일반 채팅 또는 카드 선택으로 이어진다. 기존 대화를 여는 동작과 새 대화를 만드는 동작을 구분한다.

### 4.2 채팅방

```text
대화 식별·목록 복귀·설정 진입
대화 내용
  ├─ 카드의 시작 메시지
  ├─ 사용자 메시지
  ├─ AI 응답과 생성 중 상태
  └─ 이전 기록 불러오기
메시지 작성
  ├─ 입력 중인 문장
  ├─ 전송 / 생성 중단
  └─ 큰 입력 화면 열기·복귀
필요한 보조 기능
  ├─ 현재 장면 설정
  ├─ 포켓
  └─ 활성화한 요약 플러그인
```

전송 가능·생성 중·중단 중·실패 상태를 구분한다. 대화별 초안은 방 이동 후에도 유지한다. 큰 입력 화면과 원래 입력창은 같은 문장과 커서·스크롤 상태를 이어서 사용한다.

키보드가 열려 있거나 입력 화면을 닫은 직후에도 목록 복귀와 뒤로가기가 정상적으로 동작해야 한다.

### 4.3 현재 장면과 포켓

현재 장면에서는 장소, 활성 구성 항목, 상태값, 실제로 포함되는 프롬프트 항목을 확인·변경한다. 대화마다 상태를 따로 보관한다.

포켓에서는 그 대화에 적용된 카드 버전과 현재 장면으로 상태창을 표시한다. 읽기용 포켓과 제작 중 포켓 편집을 구분한다.

## 5. 생성

### 5.1 내 제작물

| 영역 | 필요한 정보·동작 |
|---|---|
| 화면 식별 | 생성 제목, 제작자 정보 |
| 시작 동작 | 새로 만들기, 파일을 가져와 편집하기 |
| 탐색 | 제작물 검색, 전체·사용자 분류 |
| 제작물 모음 | 표지·제목·제작자, 초안·완성 상태, 편집 이어 가기 |
| 관리 | 분류·이름·고정·다중 선택·삭제 |
| 상태 | 제작물 없음, 저장 중·실패, 가져오기 진행·실패 |

서재는 사용할 작품을, 생성은 내가 제작하는 작품과 초안을 관리한다. 두 화면이 같은 카드를 보여 줄 수 있지만 별도 복제본을 만들지는 않는다.

2026-09-30 사용자 결정: 생성은 채팅과 같은 행 목록이며 상단 분류는 둥근 알약이다. 내 카드와 외부에서 받은 카드를 나눠 편집한다. 새 카드는 완료 전까지 서재에 표시하지 않는다. 서재의 외부 카드를 수정할 때에는 편집 초안과 서재 표시본을 분리하고, 완료하면 같은 카드에 반영한다. 새 UI의 구현 범위는 [UI_CREATION.md](UI_CREATION.md)에 기록한다.

### 5.2 제작기

AI와의 대화, 직접 편집, 대화 시험, 포켓 편집은 **하나의 제작 초안**을 공유한다. 모드를 바꿔도 입력 내용과 작업이 유지된다.

| 작업 | 화면에 필요한 구성 |
|---|---|
| AI와 제작 | 요청 입력, 전체 또는 특정 항목 지정, 제작 대화, 변경 결과, 되돌리기, 생성 중단·실패·재시도 |
| 직접 편집 | 기본 정보, 구성 항목, 시작 상황, 공통 대화 지침, 에셋 연결 |
| 대화 시험 | 시험할 시작 상황, 시험 메시지, 입력·전송·중단, 시험 종료·다시 시작 |
| 포켓 편집 | 상태창 제목, 기본 템플릿, 표시 항목, 연결할 장소·인물·상태값, 미리보기 |
| 완료·사용 | 저장 상태, 카드로 사용, 새 대화 시작, 기존 대화에 버전 반영 |
| 파일 공유 | 내보내기, 파일 저장, 시스템 공유 |

제작 대화의 사용자 요청과 AI 답변은 구분되어야 한다. 말풍선 여부와 배치는 새 디자인 단계에서 정한다.

AI 처리 중 사용자가 직접 고친 내용을 뒤늦은 응답이 덮어쓰지 않는다. 시험 대화와 실제 대화는 구분한다.

### 5.3 카드 구성 편집

```text
기본 정보
  └─ 제목 / 소개 / 태그 / 표지 / 제작자 정보
구성 항목
  ├─ 항목 이름·프롬프트
  ├─ 연결 이미지·음원·파일
  └─ 포함 조건
     └─ 사용 여부 / 항상 / 장소·상태 조건 / 직접 활성화
시작 상황들
  ├─ 이름 / 기본 시작 지정
  ├─ 시작 프롬프트 / 상황 지침
  ├─ 사용자에게 보여 줄 인트로
  └─ 장소 / 활성 항목 / 초기 상태값
공통 대화 지침
포켓·상태창 구성
```

장르는 태그에 포함한다. 인트로는 사용자에게 보여 주는 도입이며, 시작 프롬프트는 AI 요청에도 포함되는 첫 메시지다. 둘을 같은 입력란으로 합치지 않는다.

세계·장소·인물·오브젝트·로어를 고정된 별도 화면으로 유지할지는 아직 확정하지 않는다. 사용자가 원하는 **하나의 로어북과 사용자 폴더로 관리하는 방향**을 별도 설계 항목으로 남긴다. 현재 저장 형식의 항목 종류가 새 UI의 고정 메뉴가 되어야 하는 것은 아니다.

### 5.4 코드로 만드는 카드

코드형 카드에서도 제목·소개·저장·실행·실행 종료·AI 사용 여부·실패 표시가 필요하다. 프롬프트 카드 제작기와 별도로 접근하되 같은 앱의 편집·탐색 규칙을 사용한다.

현재 HTML·CSS·JavaScript 편집·미리보기 경로를 기능 목록으로 남긴다. 임의 언어의 네이티브 미니앱 실행이나 새로운 외부 코드 플랫폼까지 이번 UI 재설계에서 구현된 것으로 간주하지 않는다.

## 6. 설정

### 6.1 설정 목록

| 항목 | 연결되는 내용 |
|---|---|
| 사용자 | 프로필 이름·이미지 편집 |
| AI | 프로바이더, 인증·연결, 모델과 생성 설정 |
| 페르소나 | 페르소나 보관·검색·편집·폴더 관리 |
| 프롬프트 | 기본 프롬프트 편집 |
| 테마 | 라이트·다크·시스템, 대화 표시 방식 |
| 언어 | 앱 표시 언어 선택 |
| 플러그인 | 설치·생성된 기능의 설정과 활성 버전 관리 |
| 정보 | 앱 소개·버전 |

### 6.2 사용자 프로필

이름과 사진을 편집한다. 사진 선택은 기기 파일·사진 선택으로 연결하고, 선택한 사진의 이동·확대·크롭·확인·취소 단계를 제공한다.

사진 편집을 취소하면 기존 이미지가 유지된다. 이름 저장 실패와 이미지 처리 실패를 별도로 표시한다.

### 6.3 AI 설정

```text
프로바이더·연결 방식 선택
인증 정보 입력 또는 지원되는 로그인
API 주소 입력·기본 주소로 되돌리기
모델 검색·선택·목록 갱신
모델별 설정
  ├─ 최대 생성 토큰
  ├─ 생각 모드·추론 강도·답변 상세도
  ├─ 사용할 도구
  └─ 지원되는 추가 옵션
지원되는 이미지·영상·음성 모델 선택
공통 응답 설정
저장·연결·모델 목록의 오류 상태
```

선택한 서비스와 모델이 지원하는 항목만 노출한다. 인증 정보, 일반 문자열, 숫자 입력을 구분한다. API 주소에는 기본값으로 되돌리는 동작을 둔다.

### 6.4 페르소나

목록에는 검색, 생성, 폴더 경로, 페르소나·하위 폴더, 선택 상태가 필요하다. 페르소나는 이미지·이름·설명을 가진다.

항목을 열면 편집으로 이동한다. 이 페이지에서 보관 중인 항목을 눌렀다는 이유만으로 대화에 적용하지 않는다. 실제 사용할 페르소나 선택과 보관함 관리의 역할을 구분한다.

폴더 생성·이름 변경·중첩 탐색·이동, 다중 선택·해제·삭제 확인이 필요하다. 페르소나의 이름은 페르소나 편집에서 바꾼다.

### 6.5 플러그인

현재 대화 요약 기능을 기준으로 요청 작성, AI 생성·중단, 결과·권한 검토, 예제 미리보기, 적용·비활성화, 버전 기록·복원을 남긴다. 실제 대화에 붙는 실행·결과 표시와 설정 화면을 구분한다.

## 7. 화면들이 공유할 동작 구조

| 공통 구조 | 필요한 내용 |
|---|---|
| 화면 탐색 | 화면 제목, 이전 화면, 가능한 주요 동작 |
| 검색·분류 | 검색어, 선택한 범위, 지우기, 결과 없음 |
| 항목 관리 | 대상 정보, 가능한 동작, 닫기 |
| 선택 모드 | 선택 여부·개수, 전체 선택, 취소, 현재 가능한 관리 동작 |
| 삭제 확인 | 대상과 영향, 삭제 확정, 취소, 진행·실패 |
| 폴더 이동 | 현재 경로, 상위·하위 폴더, 새 폴더, 이동 대상, 목적지 확정 |
| 짧은 입력 | 항목 이름, 현재 값, 검증, 완료, 닫기, 필요한 경우 기본값 복원 |
| 긴 입력 | 항목 이름, 본문, 키보드, 스크롤, 완료·닫기, 원래 화면으로 복귀 |
| 선택 목록 | 선택 가능한 항목, 현재 선택, 필요한 검색·설명, 선택 완료 |
| 이미지 편집 | 원본, 사용 범위, 이동·확대, 적용·취소 |
| 파일 입출력 | 대상 파일, 형식 검사, 진행, 완료·실패 |
| 안내 | 작업 결과, 오류, 재시도 |

같은 기능을 서재·채팅·생성·페르소나에서 각각 다른 방식으로 구현하지 않는다. 선택을 시작하는 제스처, 선택 시 내비게이션 노출, 확인 버튼의 순서, 팝업 종류는 새 디자인에서 한 번 정하고 공통으로 적용한다.

삭제 확인은 확정 전 내용을 지우지 않는다. 삭제 취소 시 선택 상태도 해제한다. 폴더 삭제와 안의 항목 삭제를 구분하고, 새 폴더를 만들 때 이동할 목적지 탐색 상태를 잃지 않는다.

편집 화면을 닫는 동작과 수정 내용을 취소하는 동작은 구분한다. 현재 자동 저장되는 필드를 새 UI에서 ‘취소하면 되돌림’으로 표시하려면 저장 동작도 함께 설계해야 한다.

## 8. 화면 상태와 이동 시 보존할 것

모든 화면은 정상 내용 외에 로딩, 빈 상태, 검색 결과 없음, 작업 중, 실패·재시도, 키보드 표시, 선택 중, 다른 화면에 가려짐을 필요한 범위에서 다룬다.

- 탭을 오가도 검색어·선택한 분류·목록 위치를 이어 갈 수 있어야 한다.
- 채팅과 제작기의 초안은 화면 전환 때문에 사라지지 않는다.
- 팝업 안에서 다른 입력 화면을 열었다 돌아오면 원래 대상과 작성 상태로 복귀한다.
- 닫힌 화면이나 보이지 않는 탭이 입력·뒤로가기·스크롤을 가로채지 않는다.
- 길게 누르기·스크롤·텍스트 선택을 일반 클릭과 혼동하지 않는다.
- 상단·하단 탐색, 선택 모드, 키보드가 콘텐츠나 서로의 터치 영역을 겹쳐 가리지 않는다.

애니메이션의 방향·시간·탄성이나 스크롤 시 바를 숨길지는 다음 디자인에서 정한다.
