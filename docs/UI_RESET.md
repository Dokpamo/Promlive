# UI 새 출발 · 2026-09-29

사용자가 기존 화면 위에 새 상·하단 바를 덧붙인 결과를 거부했다. **별도 `src/ui` 폴더에서 새 UI를 만들고 앱의 실제 진입점을 교체한다.** 기존 화면을 유지하며 외형만 바꾸는 방식은 중단한다.

## 지금 실행되는 화면

```text
index.js / web/main.tsx
└─ App.tsx
   └─ src/ui/App.tsx
      ├─ Header: 왼쪽 제목 + 오른쪽 아이콘 (서재: 검색 → 추가)
      ├─ 서재: 3:4 표지의 3열 그리드 + 요청 시 열리는 검색
      ├─ 채팅·생성·설정: 빈 본문
      └─ TabBar: 서재 / 채팅 / 생성 / 설정
```

- 하단 탭과 새 서재 검색이 동작한다. 선택한 탭에 맞춰 제목·선택 아이콘·본문이 바뀐다.
- 서재에는 사용자 후속 요청에 따라 3열 이미지 그리드를 새로 추가했다. 로컬 미리보기 표지 12개이며, 기존 카드 저장소를 읽거나 쓰지 않는다. 카드 상세·선택 동작은 연결하지 않았다.
- 서재 검색 버튼은 플러스 왼쪽에 있으며, 누르면 새 검색 필드를 연다. 미리보기 카드의 제목·캐릭터·제작자를 검색하고 검색어 지우기·닫기를 제공한다.
- 추가·작성 아이콘은 계속 비활성이다. 파일 선택기, 새 채팅, 제작기, 프로필 편집 등을 열지 않는다.
- 프로필 정보, 설정 메뉴, 팝업, 제스처, 구형 애니메이션을 붙이지 않는다.
- 흰 배경, 고정 상·하단 바, 생성 아이콘에 회색 배경 없음. OS 안전 영역은 별도로 확보한다.
- 저장소, Workspace, AI 설정, 프로필·페르소나 저장소를 초기화하거나 구독하지 않는다. 기존 사용자 데이터 파일은 지우지 않는다.

## 코드 경계

새 UI는 `react`, `react-native`, `react-native-safe-area-context`와 **`src/ui` 내부 파일만** 불러온다. 네이티브 시작 화면 해제와 OS 상태바 색상만 플랫폼 브리지로 처리한다.

`src/app`, `src/features`, `src/layout`, `src/design`의 기존 화면·스타일·상태 관리자는 새 앱 실행 경로에 없다. 기존 소스는 복구·기능 이관 참고용으로 남아 있으며, 실행 가능한 구형 모드나 전환 스위치는 제공하지 않는다. 교체 전 진입점과 웹 CSS는 `archive/ui-before-reset-2026-09-29/*.snapshot`에 따로 보관했다.

기존 내부 구조와 필요한 기능 목록은 [UI_STRUCTURE.md](UI_STRUCTURE.md)에 남긴다. 참고 이미지의 치수 분석은 [UI_NAVIGATION.md](UI_NAVIGATION.md), 새 서재 그리드는 [UI_LIBRARY.md](UI_LIBRARY.md)를 따른다. 새 기능은 해당 화면을 새로 만든 후 명시적으로 연결한다.

- `tests/ui-shell.test.tsx`: 새 서재와 나머지 빈 탭의 전환, 검색·지우기·닫기, 기존 기능의 비활성 상태와 팝업이 없는 상태를 확인한다.
- Android는 앱 프로세스를 다시 실행해 이전 화면과 모달이 남아 있지 않은 상태로 확인한다.
