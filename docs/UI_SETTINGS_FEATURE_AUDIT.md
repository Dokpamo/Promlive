# 설정 화면을 위한 기존 기능 확인

2026-10-01. 생성·설정 시안을 실제 `src/ui` 앱에 적용했다. 기존 UI 컴포넌트는 가져오지 않고 아래 데이터·저장 서비스를 재사용한다. 저장 UI와 AI 응답에 실제로 적용되는 범위는 구분한다.

## 현재 진입점

`App.tsx`는 `src/ui/App.tsx`를 실행한다. `SettingsServicesProvider`가 `src/app/runtime.ts`와 기존 설정 서비스를 백그라운드에서 준비하고, `SettingsNavigator`가 실제 상세 페이지를 연다. 루트 화면은 저장소 로드를 기다리지 않는다. `ThemeProvider`는 화면 캐시의 테마를 첫 프레임에 사용하고 저장된 설정을 불러오면 조정한다. 상세 페이지는 기존 페이지 전환·뒤로가기 구조와 공통 상단 크기를 사용한다.

### 실제 응답 생성과의 연결

`SelectedProvider.connected`는 xAI + API 키 경로 + 키 + 대화 모델이 있을 때만 참이다. 요청 시작 시 모델·키·최대 생성 토큰을 캡처하고, 키 저장 완료를 확인한다. `GrokProvider`가 공식 xAI 주소로 스트리밍 요청을 보낸다. 설정 화면의 API 주소 입력을 이 어댑터의 요청 주소로 사용하지 않는다.

현재 요청에 전달되는 사용자 AI 설정은 **xAI API 키·선택한 모델·최대 생성 토큰**이다. 다른 서비스의 모델 목록 조회가 구현돼 있어도 그 서비스의 응답 생성이 연결됐다는 뜻은 아니다. OAuth 로그인, 웹/X/파일 검색·코드 도구, 모델별 추론·샘플링 옵션, 공통 답변 길이 등은 저장 UI와 실제 요청 적용을 구분해야 한다. `GrokProvider`에는 이 옵션을 전달하는 코드가 아직 없으며, 자료 조사 요청도 거부한다.

## 페르소나

`PersonaPreferences`는 계정 프로필과 독립적인 여러 개의 사용자 설정을 관리한다.

- 이름: 공백 제거 후 필수, 최대 40자.
- 설명: 최대 2,000자. 대화에서 사용할 사용자의 설정을 작성하는 필드.
- 이미지: 프로필 이미지와 같은 검증·선택·자르기 기반.
- 생성·수정·복제·삭제와 재실행 복원. 기존 항목 편집은 순서대로 저장하고 새 항목은 생성 완료 시 저장한다.
- 이름·설명 검색. 루트 검색은 폴더 안의 페르소나도 포함하고, 폴더 검색은 해당 폴더 안으로 제한한다.
- 중첩 폴더, 이름 변경, 여러 항목 선택·이동·삭제. 자기 자신/하위 폴더로 이동하는 순환은 거부한다.
- 폴더 삭제 시 선택하지 않은 내부 항목은 목록으로 옮긴다. 저장 실패 시 기존 컬렉션을 유지한다.
- 기존 정렬 정보는 보존하지만 현재 목록에 직접 순서를 바꾸는 UI는 없다.

`duplicate`는 새 편집 화면의 ‘복제’로 연결했다. 이름·설명·사진 편집은 ‘완료’에서 저장하며, 뒤로가면 작성 중 변경을 적용하지 않는다.

`selectedId`와 `select()`는 예전 저장 형식의 호환을 위해 남아 있다. 현재 관리 목록은 선택 시 편집기를 열며, 전역으로 사용할 페르소나를 선택하는 화면이 아니다. `CreationService.sendMessage`와 `buildContext`는 카드·대화 기록·장면을 사용하며 페르소나를 받아 AI 요청에 넣는 연결은 없다. 따라서 시안에 전역 ‘사용 중’ 표시를 넣지 않는다. 방별 페르소나 선택/적용은 별도의 연결 작업이다.

## 나머지 설정의 상태

- 사용자 프로필은 기존 저장 모듈을 사용한다. 테마는 기존 `appearance:theme` 키를 공유하며 새 UI 전체에 공통 팔레트로 적용한다.
- 프롬프트·언어는 이제 기기에 저장한다. 프롬프트의 실제 AI 요청 적용과 앱 전체 번역은 아직 연결하지 않았다. 상세 화면에도 이 범위를 명시한다.
- 플러그인은 `SummaryExtensions`의 대화 요약 확장 흐름이 존재한다. 임의 플러그인 설치나 범용 플러그인 스토어로 바꾸지 않는다.
- 정보 화면은 앱 이름·설명·버전이다. 확인되지 않은 데이터 내보내기 기능을 추가하지 않는다.

## 실제 앱에 적용한 구조

생성 목록 본문의 ‘새 카드 만들기’를 제거하고 상단 검색 옆 `+`로 빈 작성 화면에 진입한다. 항목을 눌러 별도 텍스트 편집기로 이동하는 구조 대신, 기본 정보·이야기·이미지 그룹 안에서 바로 입력한다. 기존 카드를 누르면 해당 내용을 불러와 같은 작성 화면에서 편집한다. 목록과 작성 화면의 알약은 한 줄을 유지하고, 폭을 넘으면 가로 스크롤한다.

AI와 페르소나 화면은 위 기능의 실제 설정 저장소에 연결한다. 모델 목록은 기본·저장 목록을 먼저 표시하고 키가 있는 연결은 기존 카탈로그 조회로 갱신한다. 새 채팅 화면의 AI 응답 생성은 이 작업에서 연결하지 않았다.

첫 설정 목록은 기존 SVG 아이콘을 유지한다. 상세 화면의 설정 항목은 왼쪽에 항목명, 오른쪽에 현재 값을 놓는다. 예를 들어 `대화 모델`과 `Grok 4.6`을 한 줄로 표시한다. 사용자의 최종 선택에 따라 **뒤로와 API 키 표시/숨김만 공통 아이콘**을 사용한다. 검색·추가·완료 등은 텍스트를 사용한다. `사용할 도구`는 왼쪽 항목명, 오른쪽 켜기/끄기 스위치로 즉시 반영한다.

프로바이더·연결 방식·모델·추론 레벨·답변 길이·테마·언어 등 선택형 항목은 **별도 페이지**로 이동한다. 현재 값에는 `선택됨`을 표시한다. 선택하면 적용 후 돌아가며, 뒤로 버튼·안드로이드 뒤로·웹 Escape는 값을 바꾸지 않고 돌아간다. 이전 화면을 유지해 스크롤 위치를 보존한다. API 키·서버 주소·모델 ID·프로젝트 ID·토큰 수는 해당 화면에서 바로 작성한다. API 키는 기본적으로 가리고 눈 아이콘으로 표시/숨김을 전환하며, 기존 `CredentialStore`에 저장한다. 일반 설정과 화면 캐시에는 키를 넣지 않는다. 페르소나 관리와 긴 글 작성도 전체 페이지다.

## 검증

기존 서비스 확인을 위해 `personas`, `ai-preferences`, `selected-provider`, `ai-settings`, `ai-catalog-cache`, `provider-catalog`, `xai-catalog` 테스트를 실행했다. 7개 파일, 101개 테스트 통과. 외부 API에 실제 인증하거나 유료 생성 요청을 보내지는 않았다.

실제 UI 통합 테스트는 선택 페이지 진입·복귀와 스크롤 보존, 키 분리 저장·서비스별 복원, 모델별 토큰·도구 복원, 페르소나 생성·수정·복제·검색·이동·재실행 복원, 공유 다크 팔레트와 첫 화면 테마 캐시를 검증한다. 생성 편집은 기존 완료·서재 반영 테스트를 새 알약 구조로 갱신했다. UI 경계 테스트는 데이터 서비스만 허용하고 이전 화면 컴포넌트 재사용은 계속 거부한다.

전체 76개 파일·638개 테스트 통과(`vitest run --maxWorkers=2`). 기본 병렬 실행의 일부 UI 테스트가 5초 제한을 넘겨 동시 실행 수를 줄여 확인했다. 타입 검사·웹 빌드도 통과했다. 이후 키보드 보정 변경은 설정 통합·UI 경계 테스트와 네이티브 화면으로 추가 확인했다.

Android S25/API 36과 iPhone 17 Pro/iOS 26.5 시뮬레이터에서 실제 상세 페이지 진입·뒤로가기·토큰 입력칸의 키보드 노출을 확인했다. Android는 고정 창에서 `KeyboardAvoidingView`가 닫힌 키보드 위치를 잘못 추정해 여백이 남았으므로 기존 네이티브 IME inset 브리지를 재사용하는 `KeyboardPage.android`로 처리한다. 카드 편집도 같은 처리를 공유한다. iOS 빌드는 이미지 선택 Pod의 오래된 최소 OS 값 때문에 `IPHONEOS_DEPLOYMENT_TARGET=15.1`을 앱과 동일하게 지정해서 통과했다.
